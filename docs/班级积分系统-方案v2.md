独立建表只多一次 JOIN，换来的是"加不加分"这件事在数据层就分得清。

#### v2.0 的两次转向

这个方案转过两次向，值得先说清楚为什么，否则读到第五章会以为前后矛盾。

**第一次**：你说"班内只有一台 Win11 触屏电脑、加分在课间、网络很稳"，于是我把 v1 的分布式设计整个拆了——没有同步、没有冲突、没有 outbox，退化成本地单机。那次是对的。

**第二次**（这一版）：你提到"班主任的电脑端"，这与"只有一台电脑"直接冲突。两台设备、两端都能写、其中一台放学还要断电——这三条合起来，本地方案全部走不通（原因见 5.1），必须把 Cloudflare Worker + D1 请回来。

所以这一版**不是回到 v1**。v1 是"多端 + 云 + 多租户"，这一版是"**两台设备 + 一个同步中枢**"：没有多租户、没有班级隔离、没有 WebSocket、没有 Durable Objects。

| 你的新约束 | 推翻了什么 | 换来了什么 |
|---|---|---|
| 有班主任办公电脑，两端都能改 | "单机单写，不存在并发冲突" | 本地优先 + 增量同步；但**只有两台设备**，冲突面窄到可以手工处理 |
| 班主任电脑端不需密码 | "每次都认证" | 电脑端靠设备配对 + 长期 token 免密；密码只在大屏端进管理模式时出现 |
| 教师大屏端要密码 | 班委刷卡即通行的设计 | 密码退化成"防误操作闸"，不是每次开机的关卡 |
| 学生可以点进自己的详情页 | 只有看板一个展示面 | 新增**查分页**，且不需要给学生建账号 |
| 要打印 | 只有导出 xlsx | HTML 模板 + WebView2 直接打印/转 PDF，零第三方依赖 |
| 学校成绩单可能是 .xls | "只支持 xlsx" | 按文件头识别，NPOI 兜住旧格式 |
| 都是高中生 | 按学段分三套模板（v2.2 已删成一套） | 模板只服务一个班，不再让人选学段；查分页措辞避开名次羞辱 |

**一句话总结**：架构回到了"客户端 + 云端"，但这次只服务两台设备，工程量大约是 v1 的三成；难点仍然在**触屏手势**和**成绩加权的公信力**，而不是同步。

## 一、场景与指标

### 1.1 一天里的真实动线

课间 10 分钟，班委或班主任站到教室前方那台一体机前，屏幕还停在上一节课的看板。手指一碰，进入记分台。他要在一分钟内把上一节课/上一整天攒下来的事录进去：第三组展示加分、五个人作业未交扣分、两个人课堂违纪。

这个过程有三个特点，直接决定设计：

1. **一批人一起录**，不是一个人一个人录。所以"框选一片 → 点一个项目 → 全部入账"是主路径，单人加分是次路径。
2. **站着操作，手臂悬空**。常用按钮必须落在屏幕下半部，屏幕顶部只放状态信息。
3. **手指比鼠标粗 10 倍**，且没有 hover、没有右键。误触是常态，撤销必须随手可得。

### 1.2 指标

| 指标 | 目标 | 说明 |
|---|---|---|
| 批量录入 10 人 × 1 项 | ≤ 15 秒 | 从进入记分台到入账完成 |
| 认人耗时（NFC 刷卡） | ≤ 0.5 秒 | 不能让班委在同学面前输密码 |
| 触控目标最小尺寸 | 56 × 56 DIP | 卡片 ≥ 190 × 120，类型按钮高 72，数字键 96 |
| 框选时帧率 | ≥ 55 fps | 4K 屏 + 核显，靠纯色与 Composition 动画保帧 |
| 撤销条停留 | 5 秒（批量）/ 3 秒（单人） | 触屏误触率远高于鼠标；超过后仍可撤，只是要进明细 |
| 明细撤销权限窗 | 班委 5 分钟；班主任本周期内 | 两个「5」不是一回事，见 6.5 |
| 一屏可见学生数 | 1920 × 1080 窗口下 ≥ 48 人 | 窗口更小时允许滚动，长按框选与滚动互不抢手势 |
| 排名计算（50 人 × 6 万条） | < 300 ms | SQLite 聚合，含成绩加权 |
| 冷启动 | < 2 s | 课间只有几分钟 |
| 数据可靠性 | 断电不丢已入账记录 | WAL + 每笔事务提交 |

### 1.3 角色收敛

任课老师不进系统，角色剩四个：

| 角色 | 身份 | 认证方式 | 能做什么 | 不能做什么 |
|---|---|---|---|---|
| **班主任** owner | 1 人 | **电脑端免密**；大屏端仅进管理模式时输 6 位密码 | 全部 | — |
| **副班主任** co_owner | 0–1 人 | 同班主任 | 除"删除班主任、转让所有权"外全部 | 转让、删 owner |
| **班委** officer | 2–6 人 | NFC 卡 / PIN | 加/减分、撤销自己 5 分钟内的批次 | 改名单、看成绩、重置、导出 |
| **查分 / 看板** viewer | 无身份 | 无 | 只读（排行榜、自己的分数） | 一切写操作 |

**为什么班主任电脑端可以免密**：那是他/她自己的电脑，Windows 已经认证过一次，再问一次密码只是仪式。安全性靠三件事兜住——token 与 Windows 账户 SID 绑定（换个账户就失效）、设置页有"退出登录"、以及所有管理操作都写 `audit_log`。

**为什么大屏端还留着密码**：那台机器在教室里，课间学生能碰到。密码在这里不是"证明你是谁"，而是**防误操作和防乱点**——一个班委或学生不该能一键清空学期数据。所以它只在改名单、改权重、删记录、重置这四个入口出现，记分全程不弹。

**任课老师想反馈课堂表现怎么办**：给一张纸质"课堂表现记录卡"或直接在群里说一句，班委课间代录，录入时备注栏写"数学课 · 张老师反馈"。系统里 `entries.note` 记来源，`operator_id` 记代录人——这样责任链是清楚的，也不会为了一个不加分的人增加一套账号体系。

## 二、身份识别：这一节是重点，也是唯一会踩坑的地方

你要"密码 / 人脸 / 指纹 / NFC 卡"四种。现实是：**这四种在"一台机器多人共用"的场景下，可用性差距极大**，其中一个基本不可行。

### 2.1 关键事实：Windows Hello 绑的是 Windows 账户，不是你的应用账户

Windows Hello（`UserConsentVerifier` / `KeyCredentialManager`）的人脸和指纹，注册时绑定在**当前登录的 Windows 用户**上，不是绑定在应用里的"张三（班委）"这条记录上。官方文档和实测都一致：同一台机器上多人使用生物识别，标准做法是每人一个 Windows 账户，锁屏界面识别后切到各自桌面。

放到教室场景里就是灾难：班委 A 刷脸 → Windows 切到 A 的桌面 → 应用不见了。所以：

> **不能用 Windows Hello 做班委身份识别。** 它只能回答"这台电脑的使用者是不是合法用户"，回答不了"现在站在屏幕前的是哪个班委"。

### 2.2 四种方式逐个体检

| 方式 | 硬件要求 | 能否支持多人 1:N | 认人速度 | 单人成本 | 结论 |
|---|---|---|---|---|---|
| **NFC 卡** | PN532 模块（¥18.8）+ M1 白卡（¥0.36/张） | **能**，卡 UID 直接映射成员 | 0.2–0.5 s | 合计 ¥22 起 | **首选**（你已选定，见 2.4） |
| **指纹** | USB 指纹仪 + 支持 1:N 的厂商 SDK | 能，但**取决于 SDK**；消费级模块多只给 1:1 | 0.5–1 s | 指纹仪 200–600 元 | 可选增强，需选型验证 |
| **人脸** | 摄像头 + 离线 1:N 识别 SDK | 能（自建模型）；Windows Hello 不能 | 1–2 s | 软件 0 元起，但模型/调优有成本 | **不建议首版做** |
| **PIN 密码** | 无 | 能 | 3–8 s（公开场合输入很尴尬） | 0 | 兜底，必须保留 |

三条判断依据：

- **NFC 是唯一"零学习成本 + 准确定位到人 + 便宜"的方案。** 班委把卡挂在校园卡套里，站到机器前碰一下，屏幕上直接出现"李思远 · 生活委员，可以记分了"。同学看不到任何按键过程，也不存在密码被偷看的问题。
- **指纹的坑在 SDK 不在硬件。** 便宜的指纹模块大多只提供 1:1 比对（模板由你自己存），做 1:N 要在本地遍历比对 6 个模板，尚可接受；但驱动稳定性、湿手识别率、SDK 授权费都要提前验证。**不要买没提供 SDK 的模块。**
- **人脸的问题有三层。** 教室一体机标配的是普通 RGB 摄像头，Windows Hello 需要红外摄像头，直接不可用；自建 1:N 识别（ONNX Runtime + ArcFace 类模型）在教室侧光、逆光、口罩下误识率会明显上升；更麻烦的是合规——**人脸属于敏感个人信息，班委多为未成年人，采集需监护人单独同意**，一旦有家长质疑，这套功能会变成负担而不是亮点。首版不做，接口留着。

### 2.3 落地策略：一条降级链 + 一套抽象

界面上永远只显示一句提示，按当前硬件能力自动切换：

```
刷卡 / 按指纹 / 输入密码   ←  可用方式自动探测，按优先级显示
```

代码上抽一层接口，四种实现互不干扰，加一种不用改业务代码：

```csharp
public interface IIdentityProvider
{
    string Method { get; }                 // "nfc" / "finger" / "face" / "pin"
    bool IsAvailable { get; }              // 硬件与驱动是否就绪
    Task<Member?> IdentifyAsync(CancellationToken ct);   // 返回 null = 超时或取消
}
```

**班主任电脑端不走这条链**——它靠配对时拿到的长期 token，见 5.6。这个接口只服务大屏端，别为了"统一"把 token 逻辑塞进来，两者解决的问题不一样。

**组合器不是"轮流等"，而是"同时开着，谁先到算谁"。** 这个区别在 PN532 方案里是必然的——串口轮询本来就是个常驻后台线程，它没法"轮到它时才开始"：

```csharp
// 刷卡：后台线程每 150 ms 寻一次卡，读到就抛事件
// PIN ：界面上一块常驻的九宫格，随时可点
// 两者同时可用，先完成的赢
public async Task<(Member member, string method)> IdentifyAsync(TimeSpan timeout)
{
    var tcs = new TaskCompletionSource<(Member, string)>();

    void OnCard(string uid) => tcs.TrySetResult((_card.Resolve(uid), "nfc"));
    void OnPin(string pin)  => tcs.TrySetResult((_pin.Verify(pin),  "pin"));

    _card.CardRead += OnCard;
    _pin.Submitted += OnPin;
    try
    {
        using var cts = new CancellationTokenSource(timeout);
        await using var _ = cts.Token.Register(() => tcs.TrySetCanceled());
        return await tcs.Task;
    }
    finally
    {
        _card.CardRead -= OnCard;
        _pin.Submitted -= OnPin;
    }
}
```

串行 `foreach + await` 的写法在这里是错的：它会先傻等刷卡超时 30 秒，用户明明想输 PIN 也点不了。

### 2.4 读卡器：PN532 + M1 白卡，¥22 的方案

你选的这套是对的，但**它和之前设想的 ACR122U 完全是两条技术路线**，必须写清楚，否则按老方案写的代码一行都用不上。

#### 硬件清单

| 件 | 型号 | 数量 | 单价 | 说明 |
|---|---|---|---|---|
| 读卡器 | PN532 二代一体式（USB 口） | 1 | ¥18.8 | 内置天线，USB 供电，读距约 2–4 cm |
| 卡 | M1 IC 白卡（CUID / F08） | 10 | ¥0.36 | 可反复改写 UID，读写寿命十万次，够用十年 |
| 合计 | | | **¥22.4** | 比一只 ACR122U 便宜 85% |

10 张卡给 2–6 个班委，剩 4–8 张备用。**白卡必须自己贴标签**——十张一模一样的白卡，掉在讲台上没人分得清是谁的。买的时候顺手要一版姓名贴，或者用马克笔写。

#### 关键差别：它不是键盘模拟

之前 2.4 写的"路径 A：键盘模拟"是 ACR122U 的能力，**PN532 没有**。PN532 是一颗 NFC 前端芯片，本身没有 USB 接口，模块上的 USB 口是**转串口芯片**（CH340 或 CP2102）冒充的。所以：

| | ACR122U | PN532 一体式 |
|---|---|---|
| 电脑看到什么 | CCID 智能卡设备 / HID 键盘 | **一个 COM 口** |
| 怎么读卡 | 系统级，刷卡自动"打字" | **自己发串口指令** |
| 要不要写代码 | 不用（隐藏 TextBox 接住就行） | **要，约 200 行** |
| 驱动 | 免驱 | **CH340 需装驱动** |
| 价格 | ¥150 | ¥18.8 |

多写的这 200 行值 ¥130，而且换来一个好处：**不依赖输入焦点**。键盘模拟方案里，只要用户点了别处、焦点跑了，刷卡就没反应；串口方案是独立线程在收，认人界面弹不弹都能读到卡。

#### 三个必须先处理的坑

**其一，指拨开关必须在 HSU（UART）档。** PN532 模块上有一组小开关选 I2C / SPI / HSU，出厂经常不在 HSU。**插上没反应，第一件事是看这个开关，不是重装驱动。** 常见标法是 `1=ON 2=OFF`，具体看模块丝印。

**其二，CH340 驱动。** Win10 之后部分版本免驱，但一体机多是装机版系统，很可能没有。表现是设备管理器里一个黄色感叹号的"未知设备"。这时装一次 CH340 驱动（厂商官网，1.5 MB），插拔一次，出现 `USB-SERIAL CH340 (COM4)` 才算通。

**其三，COM 端口号会变。** 换一个 USB 口，端口号就可能从 COM4 变 COM7。所以**不要写死端口号**，按设备描述找：

```csharp
// 按 "USB-SERIAL CH340" 这个描述找口，而不是硬编码 COM4
static string? FindPn532Port()
{
    using var searcher = new ManagementObjectSearcher(
        "SELECT Name, DeviceID FROM Win32_PnPEntity WHERE Name LIKE '%(COM%'");
    foreach (var d in searcher.Get())
    {
        var name = d["Name"]?.ToString() ?? "";
        if (name.Contains("CH340") || name.Contains("CP2102") || name.Contains("USB-SERIAL"))
            return Regex.Match(name, @"COM\d+").Value;
    }
    return null;
}
```

**不要用 libnfc。** 网上教程会让你用 Zadig 把 CH340 驱动替换成 WinUSB，然后 libnfc 才能连上——**替换之后串口就废了**，而我们要的恰恰是串口。直接 `SerialPort` 发帧，一行库都不用引。

#### 读卡：自己拼 PN532 帧

PN532 的 HSU 帧格式是固定的，不难：

```
00 00 FF  LEN  LCS  TFI  DATA...  DCS  00
         └长度┘ └补码┘ └0xD4┘        └校验┘
```

- `LEN` = TFI + DATA 的字节数
- `LCS` = `0x100 - LEN`
- `TFI` = `0xD4`（主机发）/ `0xD5`（模块回）
- `DCS` = `0x100 - (TFI + DATA 各字节和 & 0xFF)`

只需要三条命令：`GetFirmwareVersion(0x02)` 握手、`SAMConfiguration(0x14)` 初始化、`InListPassiveTarget(0x4A)` 找卡。完整实现：

```csharp
public sealed class Pn532Reader : IDisposable
{
    private readonly SerialPort _port;
    private string? _lastUid;
    private DateTime _lastSeen;

    public Pn532Reader(string comPort)
    {
        _port = new SerialPort(comPort, 115200, Parity.None, 8, StopBits.One)
        {
            ReadTimeout = 600,
            WriteTimeout = 600
        };
        _port.Open();
        _ = Send(0x02);                       // 握手：拿固件版本，顺便清空缓冲
        _ = Send(0x14, 0x01, 0x14, 0x01);     // SAMConfiguration：normal 模式
    }

    /// <summary>轮询一次。有卡返回 UID（大写 HEX，8 或 14 位），无卡返回 null。</summary>
    public string? Poll()
    {
        var pd = Send(0x4A, 0x01, 0x00);      // InListPassiveTarget: 1 张, 106 kbps Type A
        if (pd is null || pd.Length < 7 || pd[0] != 0x4B || pd[1] == 0) return null;

        int uidLen = pd[6];                   // NFCIDLength：M1 通常 4，CPU 卡 7
        if (uidLen is < 4 or > 10 || pd.Length < 7 + uidLen) return null;

        var uid = Convert.ToHexString(pd.AsSpan(7, uidLen));

        // 防连击：同一张卡 3 秒内只认一次，否则一直放着会刷出几十条
        if (uid == _lastUid && (DateTime.UtcNow - _lastSeen).TotalSeconds < 3) return null;
        _lastUid = uid;
        _lastSeen = DateTime.UtcNow;
        return uid;
    }

    private byte[]? Send(params byte[] data)
    {
        // 帧长 = 3(前导) + 1(LEN) + 1(LCS) + 1(TFI) + n(DATA) + 1(DCS) + 1(后导)
        var frame = new byte[data.Length + 8];
        frame[0] = 0x00; frame[1] = 0x00; frame[2] = 0xFF;
        frame[3] = (byte)data.Length;                    // LEN
        frame[4] = (byte)(0x100 - data.Length);          // LCS
        frame[5] = 0xD4;                                 // TFI
        data.CopyTo(frame, 6);
        byte sum = 0xD4;
        foreach (var b in data) sum += b;
        frame[^2] = (byte)(0x100 - sum);                 // DCS
        frame[^1] = 0x00;

        try
        {
            _port.DiscardInBuffer();
            _port.Write(frame, 0, frame.Length);
            return ReadResponse();                        // 解析见下方注释
        }
        catch (TimeoutException) { return null; }
        catch (IOException) { Reopen(); return null; }    // USB 松动后自动重连
    }
}
```

`ReadResponse()` 做的事：读字节流，找 `00 00 FF`，读 `LEN`，跳过 `LCS`，取 `LEN` 个字节（`0xD5` 开头），校验 `DCS`，返回去掉 `TFI` 之后的数组。这段是纯字节解析，四十行以内，不引任何 NFC 库。

**轮询线程放在 `Task.Run` 里，间隔 150 ms。** 别用 10 ms——PN532 单次寻卡要几十毫秒，喂太快会返回忙，而且没必要，人刷卡的动作是"贴上去停一下"，150 ms 完全跟得上。

#### 卡号存什么，以及它到底有多安全

**存 UID 的哈希，不存明文**：`SHA-256(uid + 固定盐)`。但要说实话——**这套方案防不住有心人**：

- CUID 卡（就是买的这种）的 UID 是**可改写**的。学生拿一部带 NFC 的安卓手机 + MCT 这类 App，贴一下就能读出班委卡的 UID，再写到自己那张白卡上。
- 就算改成"读扇区里的随机 token"（PN532 支持 M1 认证，需要 Key A），默认密钥 `FF FF FF FF FF FF` 全网都知道，改密钥也只是把门槛从"免费"抬到"要装个工具"。
- M1 的 Crypto1 加密早被攻破，认真的攻击者能 dump 整卡。

所以**把它定位成"认人"，不是"授权"**，这是唯一诚实的设计：

| 刷卡能做什么 | 刷卡不能做什么 |
|---|---|
| 把当前操作者切成某个班委 | 改名单、改分值、重置周期、导出成绩 |
| 进入记账状态 | 进入管理模式（仍需 PIN） |
| 触发审计日志 | 撤别人的批次 |

这张表就是 2.3 里那条降级链的具体落点：**卡坏了、卡丢了、卡被复制了，损失的上限是"有人冒充班委给自己加了几分"**——而每一条都记着 `identity_id`、时间、操作人，明细里查得到，班主任一眼能看出来。

三条缓解措施，成本都很低：

1. **卡丢了能立即吊销**：`identities.revoked_at` 打上时间戳，这张卡的哈希立刻失效，补一张新卡改一行数据。
2. **异常频率告警**：同一身份 1 分钟内刷 10 次以上，管理界面出一条提示。正常人不会这么刷。
3. **班委名单是公开的**：全班都知道谁有卡、卡长什么样。**匿名攻击在这里没有意义**——冒充者一定会被发现，这比任何加密都有效。

#### 读取失败怎么办

三层兜底，按顺序试：

1. **自动重连**：`IOException` 时关掉串口、等 500 ms、重开。USB 松了、休眠唤醒后串口假死，都靠这一条救回来。
2. **手动重试**：自检页给一个「重新检测」按钮，重扫 COM 口。
3. **PIN 兜底**：读卡器彻底坏了，班委仍可以用 6 位 PIN 认人（就是管理模式那套自绘九宫格）。**PIN 路径必须永远可用**，否则一块 ¥18.8 的模块坏掉，整个班就不能记分了。

### 2.5 空闲、回看板与"换人重认"

这是共用设备最容易忽略、也最容易出事的一环：

- 记分台闲置 **30 秒**自动回到看板并退出已认人状态（看板就是这个软件的"屏保"）。
- **任何一次批量入账后立即解锁身份**，下一批要重新刷卡。否则 A 刷完卡走了，B 直接接着记，账全记在 A 头上。
- 每次写入的 `entries.operator_id` 与 `identify_method` 一起落库，明细页可查"谁、用什么方式、几点记的"。
- **管理模式密码 5 分钟无操作自动退出**，退回看板。输完密码后忘了退出，是这套系统最现实的风险——班主任站在讲台上输密码改名单，改完被叫走，屏幕就这么开着，下一个班委上来就能改权重。
- **电脑端不做应用内锁屏**（免密）。它的安全边界是 Windows 锁屏 + 办公室的物理环境，不是应用自己。

### 2.6 读卡器自检：三个灯，一条判据

一体机不带 NFC，这件事反而省了一步——不用再去探测"内置模块能不能暴露 UID"。但自检页还是要留，因为**CH340 驱动和 COM 口这两件事，第一次装的时候有一半概率会卡住**，而卡住时老师只会看到"刷不了卡"。

设置页里放一个「读卡器自检」，三行状态，每行都对应一个具体的动作：

```
┌──────────────────────────────────────────────┐
│ 读卡设备                                      │
│  ○ 驱动         未找到 USB-SERIAL CH340       │
│                  → 装 CH340 驱动（1.5 MB）     │
│  ○ 串口         未找到 COM 口                  │
│                  → 换个 USB 口，重新插          │
│  ● 读卡         已就绪 · COM4 · 115200        │
│                                              │
│  [ 重新检测 ]        [ 刷卡测试 ]              │
│  最近刷卡：A1B2C3D4 · 14:32 · 李思远           │
│  最近 10 次：成功 9 / 超时 1                   │
└──────────────────────────────────────────────┘
```

**三行的判据是递进的**，任何一行红着，后面都不用看：

| 灯 | 判据 | 红灯时给的话 |
|---|---|---|
| 驱动 | `Win32_PnPEntity` 里有名字含 `CH340` / `CP2102` 的设备 | 「装 CH340 驱动，装完拔插一次」 |
| 串口 | 能从那个设备名里解析出 `COMx`，且 `SerialPort.Open()` 不抛异常 | 「换一个 USB 口试试，别用前面板的扩展口」 |
| 读卡 | 发一次 `InListPassiveTarget` 能收到 `0x4B` 响应 | 「确认模块上的指拨是 HSU 档；卡要贴在板子背面中心」 |

**判定标准只有一条：能不能读出 UID。** 驱动装了、设备管理器里能看到、但读不出号，就是不通——这三件事经常同时成立而卡读不出来，原因通常是拨码在 I2C 档。

**最后一行"成功 9 / 超时 1"是最有用的。** 单次读卡成功说明不了什么，教室里的真实情况是"十次里有一次没反应，学生就又拍又蹭"。有了这个计数，是模块坏、是卡离太远、还是 USB 供电不足，能看出趋势：

- 成功率 100% → 正常
- 成功率 60–90%，且失败集中在某几张卡 → 卡的问题（贴纸太厚、卡弯了）
- 成功率 60–90%，随机分布 → 距离问题（读距只有 2–4 cm，学生习惯悬空晃一下）
- 全部超时但自检页能读到 → 认人界面的轮询线程没起来，是代码问题

这三行状态加一个计数，能让班主任自己判断"要不要再买一个"，不用来问你。

**顺带一句**：读距 2–4 cm 是这类 ¥18.8 模块的真实水平，不是 10 cm。界面上的提示语要写「把卡贴到读卡器上」，不要写「靠近」——"靠近"会让一半人悬空 5 cm 晃，然后说这玩意儿不灵。

### 2.7 恢复码：忘密码和换设备时唯一的退路

有三件事一定会发生，而且都会把班主任挡在门外：

1. 忘了大屏端那 6 位管理模式密码；
2. 换了电脑、重装了系统，SID 变了，配对失效；
3. 一体机坏了，新机器要接管数据。

所以向导第 4 步除了设密码，还要生成一张**恢复码**：

```
恢复码（请抄下或打印，只显示这一次）

    K7QM - 3XP9 - 8RTD - W2HN

用于：忘记密码、更换电脑、重装系统后取回管理权限
注意：使用后立即失效，系统会生成新的一张
```

**设计细节，每条都有原因**：

- **16 位分 4 组**，字符集用 Crockford Base32（去掉 `I L O U`，避免和 `1 0` 混淆）。老师抄错一位就打不开，所以可读性比熵更重要——16 位 Base32 约 80 bit，对"防学生乱猜"绰绰有余。
- **只存 PBKDF2 hash**，和密码同一套参数。库被翻开也拿不到明文恢复码。
- **只能看到一次**。向导里要求"抄下来"或"打印一张恢复卡"（9.7），打印是首选——纸上那张会被塞进钱包或抽屉，手机截图会被清理。
- **用后即焚**：验证通过 → 设新密码 → 旧码作废 → 立刻显示新码。不这么做，"一次性"就是一句空话。

**必须诚实说明的安全边界**：这套锁是**界面层的闸门，不是数据库加密**。库文件是明文 SQLite，任何拿到文件的人用 DB Browser 都能读。所以恢复码防的是"学生乱点"和"忘记密码"，防不了"有人把一体机硬盘拆走"。

这个边界带来的一个好处是：**最坏情况没那么坏**。真到了密码和恢复码全丢的地步，数据还在文件里，可以用工具导出——我们不在界面上提供这个入口，但它存在。

如果哪天要真的加密，用 SQLCipher（`Microsoft.Data.Sqlite` 有对应的 provider），代价是密钥管理本身又成了一个新问题：密钥丢了，全班数据陪葬。**在没有把握之前，别加密**。

## 四、触屏交互规范

这一章是这个项目真正的护城河。功能谁都能做，触屏手感做不好，老师用两次就回到纸笔。

### 4.1 布局：按窗口尺寸算，不按屏幕尺寸算

这一节的前提变了：**窗口是普通的、可缩放的窗口，不是全屏**。所以布局参数不是"屏幕多大"，而是"窗口的 `XamlRoot.Size` 多大"——老师把窗口拖窄一点，列数就该少一列，而不是把卡片挤成一条。

**注意：XAML 里所有尺寸单位都是 DIP（逻辑像素），不是物理像素。** 4K 屏在 200% 缩放下逻辑分辨率只有 1920×1080，在 150% 下是 2560×1440。按 DIP 设计，一次覆盖所有分辨率；按物理像素设计，换一块屏就全乱。

先算可用宽度。左侧导航用 `NavigationView` 的 `LeftCompact` 模式：**默认收起成 48 DIP 的图标条，点开时以悬浮面板展开 230 DIP，不挤压内容区**。这样"有左侧导航"和"不牺牲网格宽度"同时成立——展开时是覆盖层，收起时只占 48。

```
1920（窗口宽）
 − 48   左侧导航（收起态）
 − 24   左右边距（各 12）
 − 70   7 道列间距（10 each，8 列时）
= 1778 ÷ 8 = 222   单卡宽度
```

纵向按同一套账算：

```
1080（屏幕高）
 − 32   窗口标题栏（系统绘制，不归你管）
= 1048（可用窗口高）
 − 56   顶部状态条（班级名 / 已选人数 / 同步角标）
 − 168  底部操作区（类型按钮 72 + 拇指行 56 + 上下 padding 20 + 间距 20）
 − 24   上下安全边距（各 12）
= 800   留给学生网格
  − 50  5 道行间距（10 each）
= 750   6 行
  ÷ 6 = 125   ← 单卡高度
```

**两个数都不是写死的，是算出来的。** 运行时只有一条规则：

```csharp
// 卡片有下限，列数有上下限，其余全部跟着窗口走
const double MinCardW = 210, MinCardH = 120;
double w = XamlRoot.Size.Width  - NavWidth(48) - 24;
double h = XamlRoot.Size.Height - TopBar(56) - BottomBar(168) - 24;
int cols = Math.Clamp((int)((w + 10) / (MinCardW + 10)), 4, 12);
int rows = Math.Clamp((int)((h + 10) / (MinCardH + 10)), 2, 8);
```

`MinCardW 210` 是"姓名 20 号字（4 个字 80）+ 四位数分数 34 号字（约 76）+ 16 的呼吸"并排的下限；`MinCardH 120` 是"三行文字 + 上下 8"的下限。低于这两个值卡片就不可读了，所以宁可滚动也不压。

按这套公式：1920 宽 → 8 列；1400 宽 → 6 列；1024 宽 → 4 列。**列数只在这几个档上跳，不会连续变化**——因为卡片宽度是均分的，列数一变，卡片宽度跳一档，肉眼能看出重排，这是正常的（也正是"拖窗口时不要每帧重排"的原因）。

**一屏放得下就一屏，放不下就滚。** 这不再是硬约束——因为窗口大小由老师决定，我没办法既适配 1280×720 的笔记本外接屏、又保证 48 人一屏。规则改成：

| 窗口逻辑尺寸 | 48 人怎么排 | 要不要滚 |
|---|---|---|
| **1920 × 1048**（4K @ 200% 默认） | 8 × 6，卡片约 222 × 125 | 不用，一屏放下 |
| 1600 × 900 | 6 × 4，卡片约 240 × 145 | 要滚，约两屏 |
| 1024 × 720 | 4 × 3，卡片约 230 × 140 | 要滚，约四屏 |

滚动不是问题，**滚动和框选打架才是问题**，而这一条已经被 4.3 的"长按 400 ms 之后才进框选"解决了：短距离滑动归 ScrollViewer，长按之后的拖动归框选，两者不抢同一个手势。

**卡片尺寸不足时按顺序让位**：先压"今日变化"那一行（12 → 隐藏），再压姓名（20 → 18），最后才动分数。**分数永不低于 28 DIP**——那是三米外唯一还认得出的东西，压它等于让这套界面失去意义。

**按座位排布，不是按姓名排。** 卡片网格按教室实际座位排（可配置行列），老师站在屏幕前的位置记忆和座位表一致——"第三组那一列"就是屏幕上那一列，画一条线过去就选中了。这是把空间记忆直接复用成交互，比任何搜索都快。座位行列在电脑端配，大屏端只读。

**窗口状态要记住。** 位置、尺寸、导航展开与否写进本地 `settings`，下次启动还原；超出当前屏幕时（换了一台分辨率更小的机器）夹回可见区域，不要还原到屏幕外面去。

### 4.2 操作区放在下半屏

人站着伸手，舒适区在屏幕中下部。所以：

```
┌────┬─────────────────────────────────────────────────────────┐
│    │  高三(2)班 · 第 18 周        已选 12 人        [锁定]    │  ← 状态条 56
│ 记 ├─────────────────────────────────────────────────────────┤
│ 分 │  ┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐      │
│ 看 │  │王小明││李思远││张雨欣││陈 默││ …  ││    ││    ││    │     │  ← 卡片网格
│ 查 │  │ 240 ││ 180 ││ 310 ││ 120 ││    ││    ││    ││    │     │
│ 明 │  └────┘└────┘└────┘└────┘└────┘└────┘└────┘└────┘      │
```

左侧导航收起时只占 48 DIP，图标 24、上下留白 12，一共五个入口（记分 / 看板 / 查分 / 明细 / 设置）。点 ☰ 或点图标条本身展开成 230 的悬浮面板，**展开时压在内容上而不是推挤内容**——推挤会让网格在展开瞬间重排一遍，48 张卡片同时跳位，视觉上很难看。

加分项按钮高度 72 DIP、最小宽度 160 DIP，手指按下去不会有"是不是点到了隔壁"的犹豫。**单击 = 用默认分入账（先出确认条），长按 500 ms = 输入自定义分值**（见 4.8）。危险操作（清空、重置）不放在这一排。

### 4.3 长按滑动框选（核心手势）

这一节的前提也变了：**网格可能滚动了**，所以"按下即框选"不再可行——那样每一次想滚动的滑动都会变成选中一片学生。手势必须分层，而分层的唯一分界线是**时间**：

| 手指动作 | 归谁 | 结果 |
|---|---|---|
| 按下后 400 ms 内移动超过 12 DIP | `ScrollViewer` | 正常滚动，不选中任何卡片 |
| 按下后 400 ms 内移动不超过 12 DIP，计时到点 | 框选 | 轻微震动 + 短音效，进入框选态 |
| 框选态下拖动 | 框选 | 实时画矩形，矩形内的卡片高亮 |
| 框选态下抬手 | 框选 | 矩形内全部选中，状态保留 |
| 普通短按（< 400 ms 且几乎不动） | 单击 | 选中 / 取消单张 |

**为什么是 400 ms 而不是 200 ms**：200 ms 太短，手指刚落下去还没决定要不要滑就已经进了框选，想滚动的人会被误判；600 ms 又太慢，老师会以为没反应，抬手指重按。400 ms 接近系统长按的一半，恰好是"我确实要按住"的心理阈值。

**这个设计的真正好处不是手感，是解耦。** 400 ms 内一动没动，`ScrollViewer` 的拖拽阈值就还没被突破，它根本没开始平移；此刻我们再 `CapturePointer` 并把滚动模式设成 `Disabled`，就不会和它抢。反过来，如果一按下就 `CapturePointer`，`ScrollViewer` 会先吃掉触摸，你只能靠禁滚动硬抢，而禁滚动的开关时机极难对齐——那才是"滑动框选时页面乱滚"的根因。

**进入方式**（两种）：

1. 长按任意卡片 400 ms → 进入框选态，长按的那张先选中。
2. 点底部「框选」按钮 → 直接进入，一个都不选（给"我就想框一片"的人）。

**框选行为**：

- 拖出一个矩形，**与矩形相交的卡片全部高亮**，实时更新。往回缩，超出的卡片会取消高亮——矩形比笔刷好在这里：画错了能反悔，不用清空重来。
- **重复框选是累加的。** 松手后状态保留，再长按拖第二个矩形，是并集，不是替换。这样能一次选中"第一组 + 第四组"这种不连续的区域。
- 单击某张卡片 = 选中/取消那一张（补选）。
- 顶部实时显示「已选 12 人」，底部按钮同步变成「给 12 人 +10」，**数字必须跟着手指变**，否则用户不敢松手。
- 抬手结束框选，但选择状态保留，直到点「清空选择」或完成入账。

**实现要点（三个都会卡住你）**：

*其一，用坐标算，别用命中测试。* 网格是等宽等高的，矩形可以直接反推行列区间，一次算出索引集合，O(行列)，滑动 60 fps 不掉帧：

```csharp
private readonly DispatcherTimer _holdTimer = new() { Interval = TimeSpan.FromMilliseconds(400) };
private Point _downPoint;
private Pointer _pointer;
private bool _lassoing;
private Rect _selRect;

private readonly HashSet<int> _selected = new();   // 已经确认的选择
private readonly HashSet<int> _preview  = new();   // 当前矩形内的预览（还没确认）

private void OnPointerPressed(object s, PointerRoutedEventArgs e)
{
    if (e.Pointer.PointerDeviceType != PointerDeviceType.Touch) return;   // 鼠标走普通点击
    _pointer = e.Pointer;
    _downPoint = e.GetCurrentPoint(_grid).Position;
    _holdTimer.Start();                    // 只起计时，不抢 Capture，也不碰滚动
}

private void OnPointerMoved(object s, PointerRoutedEventArgs e)
{
    var p = e.GetCurrentPoint(_grid).Position;

    if (!_lassoing)
    {
        // 还没进入框选：手指动了就说明用户想滚动，放弃这次长按
        if (Distance(p, _downPoint) > 12) _holdTimer.Stop();
        return;
    }

    _selRect = RectFrom(_downPoint, p);    // 起点到当前点的矩形
    UpdatePreview(_selRect);
}

private void OnHoldElapsed(object? s, object e)
{
    _holdTimer.Stop();
    _lassoing = true;
    _grid.CapturePointer(_pointer);
    _scroll.VerticalScrollMode   = ScrollMode.Disabled;   // 此刻才掐滚动，之前不能碰
    _scroll.HorizontalScrollMode = ScrollMode.Disabled;
    _selRect = new Rect(_downPoint, new Size(0, 0));
    if (HitIndex(_downPoint) is int i) _selected.Add(i);  // 长按的那张先选中
    RefreshVisual();
}

private void OnPointerReleased(object s, PointerRoutedEventArgs e)
{
    _holdTimer.Stop();
    if (!_lassoing) return;
    _lassoing = false;
    _selected.UnionWith(_preview);        // 松手才并入，拖错可以缩回去
    _preview.Clear();
    _grid.ReleasePointerCapture(e.Pointer);
    _scroll.VerticalScrollMode   = ScrollMode.Enabled;
    _scroll.HorizontalScrollMode = ScrollMode.Enabled;
    RefreshVisual();
}

private void UpdatePreview(Rect r)
{
    _preview.Clear();
    foreach (var idx in IndicesIn(r)) _preview.Add(idx);
    RefreshVisual();                      // 只改边框色，绝不重建网格
}

// 矩形 → 行列区间 → 索引。不遍历 UI 树，48 张卡也只是几十次算术
private IEnumerable<int> IndicesIn(Rect r)
{
    int c0 = Math.Max(0, (int)((r.Left   - _origin.X) / CellWidth));
    int c1 = Math.Min(Columns - 1, (int)((r.Right  - _origin.X) / CellWidth));
    int r0 = Math.Max(0, (int)((r.Top    - _origin.Y) / CellHeight));
    int r1 = Math.Min(Rows    - 1, (int)((r.Bottom - _origin.Y) / CellHeight));

    for (int row = r0; row <= r1; row++)
        for (int col = c0; col <= c1; col++)
        {
            int idx = row * Columns + col;
            if (idx < Students.Count) yield return idx;
        }
}
```

**"预览"和"已选"必须分成两个集合，这是最容易写错的一处。** 如果像上一版那样在 `PointerMoved` 里直接 `AddToSelection`，矩形缩回去时高亮不会消失——手指退回来了，卡片还选着，老师会以为软件卡了。分成 `_preview` / `_selected` 之后，拖动过程中只改预览，松手才并入，缩回就自然清零。

**这里用矩形而不是笔刷**，一个副作用要接受：斜着拖过一片，矩形会连带选中角落里没碰到的学生。但矩形有可见边框、能缩回、能分两次画，比"经过即选、滑错只能清空重来"更适合教室——老师可以先框一大片，再点掉两个不该选的。

*其二，400 ms 计时器要能被"移动"取消，而不是被"抬手"取消。* 只判断抬手，滑动滚动时抬手也会触发框选；只判断移动距离，又会因为手指微抖（触屏上 3–5 DIP 的抖动很常见）误取消。所以阈值取 **12 DIP**，介于抖动和真实拖动之间。

*其三，长按会触发系统右键菜单。* WinUI 在触摸长按时会发 `ContextRequested`，框选态里必须拦掉：

```csharp
private void OnContextRequested(UIElement s, ContextRequestedEventArgs e)
{
    if (_lassoing) e.Handled = true;     // 框选中不弹菜单
}
```

**边缘自动滚动**（窗口小、网格需要滚时才有用）：框选态下手指停在上下边缘 40 DIP 内，启一个 16 ms 的定时器按距离比例滚动，速度上限 12 DIP/帧；滚动的同时 `_selRect` 的起点或终点跟着内容偏移量平移，否则矩形会跟着手指"粘"在屏幕上、选不到滚动出来的那一行。

**和"全选"的关系**：全选按钮保留，但它只对**当前可见范围**生效——48 人 8×6 一屏放得下时等于全班，滚动状态下等于"这一屏"。要选全班，用两次全选或直接框。按钮文案写「全选本屏」，别写「全选」，这是两回事。

### 4.4 其他滑动操作

| 场景 | 手势 | 说明 |
|---|---|---|
| 输入自定义分值 | **长按类型按钮 500 ms** | 弹出数字键盘，预填该类型默认分；确认后按输入值入账，明细标注「自定义」。单击走默认分，同样要过确认条 |
| 撤销某条明细 | 在明细行上**左滑** | 露出「撤销」按钮，滑不到 40% 自动回弹。**不做全滑即撤销**——触屏误滑概率太高 |
| 设置权重 | 拖动滑块 | 滑块 thumb 直径 44 px，点轨道任意位置直接跳过去（不用精准拖） |
| 查看学生档案 | 卡片上**下滑**（或长按后选"详情"） | 展开最近 5 条记录 |
| 看板切榜单 | **左右滑**整屏 | 个人榜 ↔ 小组榜，比找按钮快 |

### 4.5 防误触的四道闸

触屏没有鼠标的"悬停确认"，误触是必然的，只能用制度补偿：

1. **撤销条常驻 5 秒**：入账后底部浮出「已给 12 人 · 回答问题 +10　[撤销] [备注]」，5 秒内可一键回滚整批。这条只覆盖「刚手滑」；超过 5 秒的撤回走明细左滑与批次撤销，七种情况的完整规则见 6.5。
2. **危险操作双重确认**：重置、删除学生、清空周期，用「长按 3 秒」的按钮，不用普通点击。长按有进度环，中途松手取消。
3. **写操作全部成批**：每次入账生成一个 `batch_id`，撤销是撤一整批，不会出现"撤了一半"的中间态。
4. **掌压过滤**：`PointerPressed` 里检查 `e.GetCurrentPoint(this).Properties.IsPrimary`，忽略非主指针；同时网格区域不接收 `Touch` 的 `ContactRect` 面积过大的事件（手掌接触面积通常是手指的 5 倍以上）。

### 4.6 反馈

| 事件 | 视觉 | 听觉 | 时长 |
|---|---|---|---|
| 按下卡片 | 缩放 0.96 + 底色加深 | 无 | 80 ms |
| **长按到点（进框选）** | 网格四周浮出 2 px 强调色边框 + 长按那张先亮起 | 一声低"笃" | 120 ms |
| 选中卡片 | 边框 3 px 强调色 + 右上角勾 | 轻"嗒" | 60 ms |
| 入账成功 | 分数滚动 + `+10` 浮起淡出 | 一声短"叮" | 300 / 600 ms |
| 撤销 | 数字回滚 + 撤销条收缩消失 | 反向"嗒" | 220 ms |
| 认人成功 | 姓名条从顶部滑入 | 双音 | 200 ms |
| 空闲回看板 | 整窗淡出到看板 | 无 | 400 ms |

音效必须可关（默认开、音量低）。教室嘈杂时它是"确认"而不是"表演"。

### 4.7 触屏专属的坑

| 坑 | 现象 | 对策 |
|---|---|---|
| 没有 hover | 鼠标移上去的高亮永远不会出现 | 所有 hover 效果改写成按下态；`PointerEntered` 里判断 `PointerDeviceType == Mouse` 才启用 |
| 没有右键 | 上下文菜单叫不出来 | 长按 500 ms 触发 `ContextFlyout`，或直接给"更多"按钮 |
| 双击缩放 | 快速连点触发 UI 缩放 | `ScrollViewer.ZoomMode = Disabled` |
| 触摸精度 | 手指落点有 8–10 px 偏移 | 命中区域比视觉区域大 8 px（透明 padding） |
| 手写笔 | 部分一体机配笔 | 笔走精确选择逻辑（等同鼠标），可用 `PointerDeviceType.Pen` 区分 |
| 手指遮挡 | 按下的位置被手挡住看不到结果 | 关键反馈放在**手指上方**，不要放在指尖处 |
| 屏幕反光/脏污 | 触摸失灵 | 设置页给「触摸校准」入口，重新跑一次五点校准；不在界面上留"插键盘凑合"的后路，那台机器本来就没有键盘 |

### 4.8 分值：默认分与自定义，都只多一步确认

分值有三个来源，界面上只体现为"点一下"和"长按一下"两种动作：

| 来源 | 触发方式 | 生效范围 | 界面表现 |
|---|---|---|---|
| **类型默认分** | 单击类型按钮 | 一次入账 | 底部出确认条，点「确定」入账 |
| **自定义分值** | **长按类型按钮 500 ms** | 一次入账 | 自绘数字键盘 → 出确认条 → 确定 |
| **封顶校验** | 自动，无独立入口 | 单次压回，或逐人扣减 | 键盘数字标黄"上限 50"；周期口径时按钮角标显示"余 20" |

#### 你给的三项，落进系统是这样

| 类型 | 默认分 | 封顶 | 一学期大致量级 |
|---|---|---|---|
| 回答问题 | +10 | 无 | 100–300 次 → 1000–3000 分 |
| 课上黑板演题 | +100 | 无 | 10–30 次 → 1000–3000 分 |
| 早读检查背课文 | **+50** | **单次最多 50** | 20–60 次 → 1000–3000 分 |

三项都可改名、改分、改图标、删除——和自建项完全一样（见 9.1 末节）。

**早读这一项，默认分就是上限，这是你定的，也说得通。** 它的含义变成："背完一篇，50 分；背得磕磕巴巴，长按改成 30。"默认值不再是"一个中间值"，而是"标准价"，下调才是例外。这比"默认 20、上限 50"更好理解——老师不需要在脑子里记两个数。

代价要写清楚：**默认 = 上限意味着这一项的点错代价是满额 50**，所以它比别的项更需要确认条，而确认条现在对所有分值都开着，正好覆盖。

#### 为什么所有分值都要确认，以及怎么让这一步不痛

上一版是 `|分值| ≥ 50` 才确认，你要求全部加。理由成立：**让老师记"哪些项要确认、哪些不要"本身就是负担**，而且判断标准藏在设置里，一个月后没人记得。统一之后只有一条规则——点了就出条，看一眼，确定。

代价是真实的：回答问题一节课点 20 次，每次多一步。所以确认条的设计目标是"**多一次点击，不多一次判断**"：

- **高度 88 DIP，从底部升起，盖在操作区上方，不遮网格。** 卡片全程可见，老师能继续对着学生核对。
- **「确定」按钮在右侧，宽 240 DIP，位置固定。** 点完类型按钮，拇指往右下一滑就是确认，形成肌肉记忆后这一步几乎不消耗注意力。
- **不需要移动视线。** 条上写「给 12 人 · 回答问题 +10 · 合计 +120」，人数和合计都在同一行，一眼扫完。
- **「取消」在左，且不做成危险色。** 它不是"删除"，只是"这次算了"，用普通文字按钮。

```
┌────────────────────────────────────────────────────┐
│  给 12 人 · 回答问题 +10 · 合计 +120   [取消] [确定] │
└────────────────────────────────────────────────────┘
```

三个人以上必须显示合计。单个学生时省掉"合计"，只写「王小明 · 回答问题 +10」。

**确认条本身就是最后一道防错。** 批量给 12 人各 +100，合计 +1200 这个数字只有在这一行才会出现——分数滚动的动画看不出量级，但"1200"看得出。这是把二次确认从"多一道手续"变成"多一次核对"的关键。

**不做"连点两次同一按钮即确认"这种省略。** 它省不了时间，反而会在快速操作时误触：老师连点两下想给同一批人加两次分，第二下会被当成确认。确认必须是**位置不同的另一个按钮**。

**键盘回车 = 确定，Esc = 取消**（电脑端）。大屏没有键盘，所以确认条上的按钮必须够大：确定 240 × 64，取消 120 × 64。

**确认条和撤销条共用底部那一条位置，但不同时出现。** 确认条在入账前，撤销条在入账后——点「确定」的同一帧，确认条收起、撤销条升起，视觉上是同一条横条换了内容。如果两个都显示，底部会占掉 176 DIP，正好是最后一行卡片的高度。

#### 封顶：单次 50，默认值就是 50

你定的是"单次默认 50，也是最高 50"。落进系统就是：`default_delta = 50`、`cap_value = 50`、`cap_scope = 'once'`。

| 操作 | 结果 |
|---|---|
| 单击（用默认分） | 50，**永远不撞上限**，因为两者相等 |
| 长按输入 30（背得一般） | 30，正常入账，明细显示「早读背课文 +30（默认 +50）」 |
| 长按输入 80（想多给） | 键盘数字实时变 50 并标黄「上限 50」，确定后按 50 入账 |
| 长按输入 −20（这次没背） | 允许，扣分项不受加分上限约束 |

**为什么保留"上限"这个字段，而不是干脆写死 50。** 因为这个数将来要能改：某天你想把早读提到 80 分封顶，改一个数字就行，不用改代码；而"默认分 = 上限"是一条**初始数据**上的约定，不是代码里的约束。向导里给这一项预填两个 50，老师在设置页把上限改成 80，它立刻变成"默认 50、最多 80"——同一个类型，两种用法，不需要加任何新概念。

**超限要压回并明说，不要静默。** 长按输 80，数字自己变成 50 并标黄一句"上限 50"。静默压回会让老师以为键盘坏了，然后去家长群里说这软件算错分。

**到顶后可强制超出，走管理密码。** 一学期背了 40 篇的学生，老师想再奖励，系统不该顶回去。长按超出后弹「本次按 80 计入？」+ 管理员 PIN（自绘数字键盘输入，不需要实体键盘）→ 确认后按原值计入并标 `over_cap`。**软上限的意思是"默认拦住，人可以让它过"**，硬上限的意思是"系统比老师大"，后者在教育场景一定出事。

**周期累计口径保留但默认不启用。** 字段 `cap_scope` 支持切成 `'term'`（整学期累计最多 50），入口在类型编辑的下拉里。不用它就别露出来——设置页默认只显示"单次上限"一个数字，切换口径藏在「更多」里。真要用的人会去找，不用的人不该看见。

**封顶只对加分项有意义，扣分项不设封顶**——扣分封顶等于"扣够了就可以随便违纪"。

#### 理由：大屏只能选，不能打字

**大屏端没有键盘，这一条决定了理由只能做成标签，不能做成输入框。** 系统软键盘在大屏上会遮掉半屏，而且 Touch 键盘在 kiosk 场景经常被组策略关掉——依赖它等于赌。

```
┌──────────────────────────────────────────┐
│  课上黑板演题                      [ × ]  │
│                                          │
│  理由（可选，点一下贴上）                 │
│  ┌────────┐┌────────┐┌────────┐          │
│  │ 板演满分 ││ 一题多解 ││ 纠错到位 │        │  ← 点选，不弹键盘
│  └────────┘└────────┘└────────┘          │
│                                          │
│              100                         │
│   [1] [2] [3]                            │
│   [4] [5] [6]                            │
│   [7] [8] [9]                            │
│   [ ± ] [0] [⌫]                          │
│   [        确定 +100       ]              │
└──────────────────────────────────────────┘
```

六条规则：

1. **理由永远可选。** 空着也能确认。强制填理由会把路径堵死，最后老师干脆不用。
2. **标签是文字，不是分值。** 这与本节开头"不要预设分值胶囊"不冲突——被否掉的是"一排 +1/+2/+5/+10 的分数按钮"，标签选中它不改变任何一个数字。
3. **标签来源两个，入口都在电脑端。** 内置约 12 个通用标签（"背诵流利""略有卡顿""一题多解""纠错到位""主动补做"…），加上班主任在电脑端自己加的。**大屏端只显示、只排序，不提供"新建"按钮**——没键盘，新建不了，硬给一个入口只会让人点进去发现打不了字。
4. **按使用频次排序，最多显示 6 个，超出的收进「更多」。** 老师挑标签的方式很固定，前 6 个能覆盖九成；第 7 个开始要翻，那就不是高频路径了。频次每周重算一次，别实时——实时排序会让按钮在两次点击之间换位置，反而点错。
5. **单击入账的批次，5 秒内还能补标签。** 撤销条上加一个「备注」按钮，点开是同一排标签（不弹键盘）。5 秒后撤销条消失，这个窗口就关了——理由是"记账的注脚"，不该变成可以无限编辑的账本。
6. **理由不进查分页、不进看板。** 教室里是公开屏幕，"上课睡觉""作业糊弄"这类标签一旦露出，课间就变成对质现场（与 9.5 第 3 条同源）。理由只给班主任在电脑端看，导出时作为可选列。

**要写自由文本，只能在电脑端。** 明细页选中一条记录 → 「补充备注」→ 键盘输入 → 存 `entries.note`，同时写 `audit_log`。大屏端读得到这条备注，但显示为灰色只读文本。这条路径的存在是为了"一个月后解释清楚这一分为什么是 30"，不是为了日常录入——日常录入只有标签。

#### 数字键盘的四个细节

**必须自己画，不要调系统软键盘。** 系统触屏键盘有三个毛病：弹出慢（300–500 ms，还带系统动画）、遮住半屏、样式与应用完全脱节。自己画一个按钮网格，每个 96 × 96 DIP，更快也更可控。

1. **预填该类型默认分并全选**。想给 8，按一个 8 再确定；想给 28，按两次。不预填的话每次都要先删默认值，白多两下。
2. **确认键显示最终结果**（「确定 +100」），不是光写「确定」。批量给 12 人操作时，这一眼能防住数量级错误。
3. **面板从底部升起，不居中。** 拇指在下面，键盘也放下面，眼睛和手不用上下跑。
4. **标签行贴在数字上方，不要放到面板顶部。** 手指在动，视线也跟着在动——把标签放在标题下面就等于让人每次抬头。标签是 40 高的胶囊，点一下选中、再点取消，**一次最多选两个**（"背诵流利 + 声音洪亮"）。**整行标签不能获得焦点**，否则 WinUI 会尝试弹输入法，虽然系统键盘在这种控件上大概率不弹，但一旦弹出来，整块面板就被顶掉一半。

**± 键保留**：偶尔要把加分项临时当扣分用，这比再建一个负分类型灵活。确认条对正负一视同仁——+80 和 −80 都要看一眼。

**批量时自定义值作用于全部已选学生**（封顶项除外，见上）。要逐人不同，就分两批录——这不是系统该替老师做的决定。

**明细要能看出改过什么**：`entries` 同时存 `delta`（实际值）和 `rule_delta_default`（当时的默认值），两者不等时明细显示「课上黑板演题 +80（默认 +100）」。否则一个月后没人说得清这条为什么是 80。

**历史不会被污染**：每条记录存的是数值快照，不是对类型分值的引用。之后把「回答问题」从 +10 改成 +5，已记录的那 137 条仍是 +10。

### 4.9 4K 屏：三件必须先处理的事

**一、先搞清系统缩放，再谈布局。**

4K 面板是 3840×2160 物理像素，但 Windows 会按缩放换算成逻辑分辨率，XAML 认的是逻辑值。所以：

> **4K 本身不给你更多空间，缩放才给。** 65" 教室大屏通常设 200%，逻辑尺寸和 1080p 一模一样——这时按窗口算列数的逻辑完全不变，只是卡片物理上更大、更好按。别按 3840 去设计网格，你会做出一个只能放 12 个学生的界面。

启动时读一次窗口的逻辑尺寸，动态决定列数，而不是写死：

```csharp
// XamlRoot.Size 本身就是 DIP（已含缩放），不要再除以 RasterizationScale
// 只在 SizeChanged 里重算列数，别在每帧算
private void OnRootSizeChanged(object s, SizeChangedEventArgs e)
{
    Columns = Math.Clamp((int)((e.NewSize.Width - NavW - 24 + Gap) / (MinCardW + Gap)), 4, 12);
    RebuildGrid();          // 列数变了才重建，行数由人数决定
}
```

**窗口化管理下还有一个新坑：拖窗口边缘时 `SizeChanged` 每帧都发。** 别在里面重建网格——用 150 ms 的防抖，松手后重排一次；拖动过程中只让卡片等比缩放（`Stretch` 布局自己会做），否则拖一次窗口会看到 48 张卡疯狂闪烁。

**二、必须声明 PerMonitorV2，否则触摸会点偏。**

这是 4K 触屏最经典的坑：应用没做 DPI 感知时，系统用位图拉伸来显示窗口，视觉上发虚，**触摸坐标与 XAML 坐标之间出现按比例放大的偏移**，越靠屏幕右下角偏得越多。现象是"点左边的学生，右边那个被选中"，而且**只在手指触摸时出现，鼠标完全正常**——极难排查，很多人会误判成手势逻辑写错了。

```xml
<!-- app.manifest -->
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2</dpiAwareness>
    <dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true/pm</dpiAware>
  </windowsSettings>
</application>
```

**三、4K 上别用"好看"的效果。**

4K 的渲染缓冲区是 1080p 的 4 倍，而教室一体机多半是核显（Intel UHD / Iris Xe）。下面这些效果会把帧率打到 30 以下，而滑动框选必须 55 fps 以上才跟手：

| 别用 | 换成 |
|---|---|
| 卡片投影 `Shadow` | 1 px 描边 + 纯色底 |
| Mica / Acrylic 背景 | 纯色（`#12161C`） |
| 逐帧 XAML 动画 | Composition 动画（`ScalarKeyFrameAnimation`） |
| 每卡独立 `DropShadow` | 选中只改边框色 |
| 大图 / 渐变背景 | 无背景图 |

另外把主题固定为 Dark，避免系统切主题时整屏重绘；卡片网格用 `ItemsRepeater` + `UniformGridLayout` 保持虚拟化，别用 `StackPanel` 一次性铺 50 个含阴影的容器。

## 五、架构

### 5.1 为什么会回到云端

前一版我把它压成了单机，前提是"班内只有一台电脑"。现在多了一台班主任的办公电脑，这个前提不成立，而三条可能的替代路线都走不通：

| 路线 | 为什么不行 |
|---|---|
| 两台电脑共享同一个 SQLite 文件（放共享目录） | **SQLite 官方明确警告**：网络文件系统上文件锁不可靠，WAL 模式会直接损坏数据库。不是慢，是坏 |
| 一体机当服务器，电脑端局域网直连 | 技术上可行，但**一体机放学就断电**。班主任晚上在办公室改名单、算成绩，全落空 |
| 网盘同步数据库文件 | 两端同时在线时互相覆盖，且没有冲突检测。这是最坏的一种"看起来能用" |

所以需要一个中立位置：**Cloudflare Worker + D1**。它解决的不是"实时协作"，而是**两台设备不同时开机也能拿到同一份数据**——这恰恰是本地方案做不到的。

```
                          ▼
              ┌───────────────────────┐
              │  D1（SQLite）          │  唯一真相源
              └───────────┬───────────┘
                          ▼
              ┌───────────────────────┐
              │  R2（导出与备份）      │
              └───────────────────────┘
```

**D1 是唯一真相源，但它不是唯一的数据副本。** 两端的本地 SQLite 都是完整镜像，界面只读本地库。这句话是整个架构的地基：它同时保证了"点下去立刻有反馈"和"断网照样能用"。

### 5.3 两端不是对等的

| | 大屏端（教室一体机） | 电脑端（办公室） |
|---|---|---|
| 写频率 | 高：课间批量，一次几十条 | 低：改名单、导成绩，一天几次 |
| 延迟要求 | **< 100 ms**，慢了老师就放弃 | 几百毫秒无感 |
| 离线容忍 | 断网时记分不阻塞即可（教室网络稳，不做「连续 500 次」这种硬指标） | 能看缓存、能排队即可 |
| 主要风险 | 一体机休眠唤醒后连接假死（比真断网更常见） | 与另一端的数据新旧不一致 |
| 认证 | 班委刷卡；进管理模式要班主任密码 | **免密**（见 5.6） |

所以两端的 outbox 强度不同：一体机是"绝不阻塞"，电脑端是"阻塞但明确提示"。不要写一套通用的同步引擎再配置两份参数——那比写两份薄实现更容易出 bug。

### 5.4 同步协议

**增量拉取**：

```
GET /api/v1/sync?since=1024&limit=500
→ { "students": [...], "rules": [...], "entries": [...],
    "next": 1531, "hasMore": true, "serverTime": 1762...  }
```

`since` 用服务端自增 `seq`，不用时间戳——客户端时钟不可信，一台系统时间错乱的电脑会永久卡住或重复拉取。

**写入**：

```
POST   /api/v1/entries        批量 1–50 条，整批一个事务
POST   /api/v1/students       单条新增（带客户端 UUID，重传幂等）
PATCH  /api/v1/students/:id   修改（带 If-Match: rev）
PATCH  /api/v1/rules/:id      同上
```

每条记录带客户端生成的 **UUIDv7** 作为主键，`INSERT OR IGNORE` 保证重传不重复计分。这是唯一需要的幂等机制。

**节奏**：前台 4 秒轮询，最小化/后台降到 30 秒，窗口重新激活时立刻拉一次。不用 WebSocket，也不用 Durable Objects——两台设备的场景不值得为"实时"付这个复杂度。

### 5.5 冲突：其实只有两类

先分清哪些会冲突、哪些根本不会：

| 数据 | 会不会冲突 | 处理 |
|---|---|---|
| `entries`（积分流水） | **不会**。只追加，UUID 主键，两台设备各插各的 | 无需任何处理 |
| `exam_scores`（成绩） | 基本不会。谁导入谁负责，同一场考试重复导入覆盖 | 按 `(exam_id, student_id)` 覆盖 |
| `students` / `rules` / `members` | **会**。两端都可能改同一个学生 | 乐观锁：`rev` 自增，`PATCH` 带 `If-Match: rev`，不匹配返回 409 |
| `periods`（重置） | **会，且最危险** | 见下 |

冲突率最高的其实是两个班主任（或班主任 + 副班主任）同时改名单，这在现实中一个月也遇不到一次。所以**不要做三方合并，不要做 CRDT**。409 之后给一个朴素的选择框：

```
这个学生刚在教室电脑上被改过（姓名：王小明 → 王筱铭）
  [ 用我的 ]   [ 用教室那台的 ]   [ 手动合并 ]
```

**重置是唯一必须加锁的操作。** 一体机上点"重置学期"时，如果电脑端正在导入成绩，两边对"当前周期"的理解会分叉，导致一部分记录落到已归档的周期里。对策：重置先向 Worker 申请一个重置令牌（90 秒有效，归档进行中每 45 秒续期），Worker 把班级标记为 `resetting`，两端在此期间拒绝写入非重置类操作，重置提交后释放。详见 8.1。这比"最后写入胜"安全，也比分布式锁便宜。

### 5.6 认证：两种端，两种策略

**电脑端免密**，这是你定的，也确实合理——那是班主任自己的电脑，Windows 已经登录过一次了，再问一次密码只是仪式。做法：

1. **首次配对**：在电脑端输入班级码 + 班主任密码（或刷班主任卡），Worker 返回一对 token。
2. **长期免密**：refresh token（90 天）用 **DPAPI 加密后存文件**，access token（12 小时）过期时静默续期。用户感知不到。
3. **换人防呆**：DPAPI 用 `DataProtectionScope.CurrentUser`，密文只有当前 Windows 账户能解开。同一台电脑换个账户登录，token 直接解不开，要求重新配对——这挡住了"同事借用电脑顺手看一眼全班成绩"。

**为什么不用 `PasswordVault`（上一版写错了）。** 那是 UWP 的 API，在 full-trust 桌面应用里行为不同：微软在 WindowsAppSDK 的 issue 里已确认它在 WinUI 3 / WPF 里"不能按预期工作"，凭据会写进**所有桌面应用共享的存储**（在凭据管理器里能直接看到），并不按应用隔离。我们又是 unpackaged，连包身份都没有，指望它隔离纯属自欺。DPAPI 是 Win32 时代的老东西，但它正好只做一件事：**只有这个用户能解开**。

```csharp
// %LOCALAPPDATA%\ClassPoints\session.bin
var blob = ProtectedData.Protect(
    Encoding.UTF8.GetBytes(refreshToken),
    s_entropy,                              // 固定应用盐，防同用户下别的程序直接复用密文
    DataProtectionScope.CurrentUser);
File.WriteAllBytes(path, blob);
```

文件再叠一层 ACL 只给当前用户，成本一行 `FileSecurity`。**注意 unpackaged 应用不能用 `ApplicationData.Current`**（会抛 `COMException`），所有本地路径自己拼 `%LOCALAPPDATA%`——这条同样适用于 10.4 的数据库文件。
4. **兜底**：设置页有"退出登录"，换班主任时点一下。

**大屏端需要密码，但只在进管理模式时**（这是你选的）：班委刷卡记分全程不弹任何密码框；一旦要改名单、改权重、删记录、重置，弹班主任密码。密码在这里的作用不是"证明你是谁"，而是**防误操作和防学生乱点**——一个班委或学生不该能一键清空学期数据。

角色收敛成三个：

| 角色 | 身份 | 认证 | 能做什么 |
|---|---|---|---|
| **班主任** owner | 1 人 | 电脑端免密；大屏端仅管理操作要密码 | 全部，含重置、导出、授权 |
| **副班主任** co_owner | 0–1 人 | 同班主任 | 除"删除班主任、转让所有权"外的全部；用于互为备份 |
| **班委** officer | 2–6 人 | NFC 卡 / PIN | 加/减分、撤销自己 5 分钟内的批次 |
| **看板 / 查分** viewer | 无身份 | 无 | 只读 |

### 5.7 数据放哪：Cloudflare 为主，国内云留门

名单、成绩、行为记录是未成年人个人信息。Cloudflare 在中国大陆没有可用节点，数据实际落在境外（通常香港/新加坡/美西）。严格讲这构成**个人信息出境**，而《个人信息保护法》对不满十四周岁未成年人的信息要求监护人单独同意，十五到十八岁的虽不适用该条，但仍属未成年人个人信息。

你定的是"都兼容，以 Cloudflare 为主"。这个决定可行，但**"兼容"必须落到三层具体的东西上**，否则就是一句口号：

| 层 | 做法 | 换云时改什么 |
|---|---|---|
| **接口契约** | 客户端只认 `POST /api/v1/entries` 这类路径和 JSON 结构，不认 Worker、不认 D1 | 不改。客户端一个字节都不动 |
| **数据访问** | `Repository` 接口 + 两个实现：`D1Repository`（默认）、`SqlRepository`（PostgreSQL / MySQL） | 换 DI 注册的一行 |
| **SQL 方言** | 所有方言差异集中在一个 `SqlDialect` 里，不散落在业务查询中 | 补一个方言类 |

方言差异比想象中小，真正要处理的只有五处：

```csharp
public interface ISqlDialect
{
    string Now();                       // SQLite: datetime('now') / PG: now()
    string UpsertIgnore(string table);  // INSERT OR IGNORE / ON CONFLICT DO NOTHING
    string LimitOffset(int limit, int offset);  // LIMIT ? OFFSET ? 两边一样，但 D1 对参数顺序敏感
    string JsonExtract(string col, string path); // json_extract / col->>path
    bool SupportsReturning { get; }     // D1 支持，MySQL 8 不支持，得回查一次
}
```

**这五处不集中的话，换云那天你会改四十个文件。** 集中了，就是一个类加一次回归测试。

数据搬迁也给一条能跑的路，而不是一句"导出一下"：

```bash
# 1. 从 D1 导出成标准 SQLite 的 SQL
npx wrangler d1 export classpoints --remote --output dump.sql

# 2. 还原成一个本地 sqlite 文件，再逐表导 CSV（比解析 SQL 稳）
sqlite3 classpoints.db < dump.sql
sqlite3 classpoints.db <<'SQL'
.mode csv
.headers on
.once students.csv
SELECT * FROM students;
SQL

# 3. 目标库 COPY / LOAD DATA INFILE 导入
#    最后一步不能忘：把 seq 的序列重置到 max(seq)
```

顺序必须是 **先导数据、再切客户端指向**，不能反过来。

**"兼容"真正的成本不在方言，在两件事上，而这两件现在做是零成本：**

1. **所有主键用客户端生成的 UUID**（v7，带时间前缀，索引友好），不用自增 ID。一旦用了自增，换库之后所有外键全对不上，那是真重写。
2. **所有 SQL 写在一个文件里**（`Data/Sql.cs`），不散落在各个 ViewModel 里。换云那天你打开这一个文件就能数清楚要改多少行。

**一句实话**：自己班用、不对外、不上报学校，跑 D1 没有任何实际问题；要往年级推广，再走上面这条路，代码改动约一天，不是重写。所以现在按 D1 写，别为了"兼容"提前搭两层抽象——**提前抽方言只会让你多写一堆用不上的分支，而 UUID 主键和集中放 SQL 这两件事，本来就是这个架构本来就该有的样子。**

### 5.8 离线降级

三条规则，按优先级：

1. **本地写入永远先成功**。UI 不等网络，写本地库 → 标记 `synced = 0` → 进 outbox。
2. **拉取失败不报错**。静默重试，界面上只用一个角标显示"待同步 3 条"和"最后同步：2 分钟前"。
3. **两端都断网也能工作**。各自记各自的，恢复后靠 UUID 幂等合并——这正是 entries 只追加换来的好处。

**你说教室网络很稳，所以这里可以砍一刀。** outbox 要留（成本极低，写本地库时顺手就写了），但下面这些可以省掉：

| 可以砍 | 为什么 | 省下的时间 |
|---|---|---|
| 长时间离线的合并优化（几百条排序、压缩、分段提交） | 网络稳，队列几乎不会积压超过十几条 | 2 天 |
| 本地冲突预判（提前 diff 出可能冲突的字段） | 409 来了再处理，一个月遇不到一次 | 1.5 天 |
| 离线态下的完整功能可用性（导出、打印、成绩导入） | 这些是电脑端的活，办公室有网 | 1 天 |

**不能砍的只有一条：本地写入先成功。** 它不是为断网准备的，而是为"点下去 100 ms 内必须有反馈"准备的——哪怕网络完全正常，等一次 HTTPS 往返（尤其跨境到 Cloudflare）也要 100–300 ms，触屏上这个延迟就是"卡"。

顺带说一个比断网更常见的故障：**一体机休眠唤醒后，TCP 连接是假活的**——`HttpClient` 不报错，请求就那么挂着。所以每次 `Window.Activated` 都要主动探测一次（发一个 `/ping`，2 秒超时），超时就重建连接。这条比任何离线逻辑都更值得先写。

必须做的一件事：**首次配对成功前，应用是只读的**。没有云端数据就没有班级、没有名单，不能让人在一个空库里开始记分，事后再去"合并"两份名单。

## 六、数据模型

### 6.1 三条叠加的原则

**其一，`entries` 只追加。** 总分永远由 `SUM(delta)` 现算，撤销是插入一条 `delta` 取反、`reverses_entry_id` 指向原记录的行。理由从"避免并发冲突"变成了"**教育场景的数据必须可追溯**"——家长问"我家孩子这 5 分是怎么扣的"，你要能翻出每一条记录、操作人、时间。直接改总分字段的写法，事后无法解释。

**其二，本地库是镜像，云端才是真相源。** 两端的 SQLite 都有完整数据，但任何一端的本地修改在推上去之前都是"待定"状态。这决定了界面只能读本地库（否则断网白屏），也决定了 `entries` 必须带一个客户端生成的 `id`：它既是主键，也是重传时的幂等键。

**其三，删除一律软删除。** 这条是同步带来的，不做会出诡异问题：

> 教室电脑上删掉了转学的李思远，班主任电脑不知道。第二天班主任电脑联网，把它本地的旧数据推上去——李思远复活了，还带着全部历史分。

所以所有实体表都有 `deleted_at`，删除只是打时间戳，所有查询默认过滤。墓碑要保留至少一个学期再物理清理，否则迟到的设备仍会把它推回来。

**并发修改用 `rev` 乐观锁。** `students` / `rules` / `members` 各带一个自增 `rev`，`PATCH` 时带 `If-Match: rev`，不匹配返回 409 让用户选。不做三方合并——两台设备上同时改同一个学生的姓名，一个月也遇不到一次。

### 6.2 表结构

| 表 | 作用 | 说明 |
|---|---|---|
| `students` | 学生 | 学号可选，**不参与成绩单匹配**（只按姓名对） |
| `members` | 班主任 / 副班主任 / 班委 | `role`、`pin_hash`（仅大屏端管理模式用） |
| `identities` | 身份凭证 | 一个成员可挂多张卡 / 多个指纹 |
| `rules` | 加分项（类型） | 默认分值、图标、排序、归档；`cap_value` / `cap_scope` 管封顶；`preset_key` 只供「恢复默认预设」识别 |
| `entries` | 积分流水 | 事实表，`period_id` 划分周期；`note` 是理由快照，`capped` / `over_cap` 记封顶结果 |
| `note_templates` | 常用理由 | 文本 + 使用次数，跨类型共用；不做多租户，一个班一份 |
| `periods` | 积分周期 | 重置 = 归档 + 新建；`term_key` 标记学期归属，总评按它跨周期聚合 |
| `exams` | 考试 | 名称、日期、满分（默认 750，可改）；**没有科目字段** |
| `exam_scores` | 成绩 | 每人每场一个总分，外加缺考标记；**没有单科** |
| `schemes` | 权重方案 | 考试占比、平时占比、`normalize` 口径开关（默认 0 = 原值加权）；多套并存但仅一套 `is_active` |
| `scheme_weights` | 各场考试权重 | 与方案绑定，合计 100% |
| `settings` | 配置 | 座位布局、空闲回看板时长等 |
| `audit_log` | 敏感操作 | 重置、删除、导出 |
| `backups` | 备份记录 | 路径、时间、条数校验 |
| `outbox` | **仅本地**：待推送队列 | 断网/断电后重放，含重试次数与下次时间 |
| `sync_state` | **仅本地**：同步游标 | `last_seq`、`last_pull_at`、token 引用的键名 |

### 6.3 DDL

```sql
-- 学生
CREATE TABLE students (
  id          TEXT PRIMARY KEY,             -- 客户端 UUIDv7
  name        TEXT NOT NULL,
  student_no  TEXT,                         -- 学号，可选；不参与成绩单匹配（只按姓名对）
  seat_no     INTEGER,
  group_name  TEXT,
  active      INTEGER NOT NULL DEFAULT 1,
  rev         INTEGER NOT NULL DEFAULT 1,   -- 乐观锁，每次改自增
  updated_at  INTEGER NOT NULL,             -- 增量拉取用
  deleted_at  INTEGER,                      -- 软删除：同步下不能硬删
  created_at  INTEGER NOT NULL
);
CREATE INDEX idx_students_updated ON students(updated_at);
CREATE INDEX idx_students_seat ON students(active, seat_no);
CREATE UNIQUE INDEX uq_students_no ON students(student_no) WHERE student_no IS NOT NULL;

-- 成员（班主任 / 班委）
CREATE TABLE members (
  id           TEXT PRIMARY KEY,
  display_name TEXT NOT NULL,
  role         TEXT NOT NULL CHECK (role IN ('owner','co_owner','officer')),
  pin_hash     TEXT,                        -- 大屏端进管理模式用；电脑端免密不发这个
  created_at   INTEGER NOT NULL,
  revoked_at   INTEGER,
  rev          INTEGER NOT NULL DEFAULT 1,
  updated_at   INTEGER NOT NULL,
  deleted_at   INTEGER
);

-- 身份凭证：一个成员可以有多张卡、多个指纹
CREATE TABLE identities (
  id          TEXT PRIMARY KEY,
  member_id   TEXT NOT NULL REFERENCES members(id),
  method      TEXT NOT NULL CHECK (method IN ('nfc','finger','face','pin')),
  credential  TEXT NOT NULL,                -- 卡号/模板的 SHA-256(salt||raw)，不存明文
  label       TEXT,                         -- "校园卡"、"备用卡"
  created_at  INTEGER NOT NULL,
  last_used_at INTEGER
);
CREATE UNIQUE INDEX uq_identities_cred ON identities(method, credential);

-- 加分项（类型）
CREATE TABLE rules (
  id          TEXT PRIMARY KEY,
  label       TEXT NOT NULL,
  delta       INTEGER NOT NULL,             -- 该类型的默认分，正加负扣
  icon        TEXT,
  sort        INTEGER NOT NULL DEFAULT 0,
  preset_key  TEXT UNIQUE,                  -- 仅记录"来自预设"，为空即完全自建
  -- 封顶：cap_scope='single' 单次上限；'period' 周期累计上限；NULL 不封顶
  cap_value   INTEGER CHECK (cap_value IS NULL OR cap_value > 0),
  cap_scope   TEXT CHECK (cap_scope IN ('single','period')),
  -- 没有 require_confirm 字段：确认条对所有分值恒定生效，不做成数据
  archived_at INTEGER,
  rev         INTEGER NOT NULL DEFAULT 1,
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER,
  CHECK (cap_value IS NULL OR cap_scope IS NOT NULL)
);
CREATE INDEX idx_rules_updated ON rules(updated_at);

-- 理由标签：跨类型共用，按使用频次排序取前 6
CREATE TABLE note_templates (
  id           TEXT PRIMARY KEY,
  text         TEXT NOT NULL,
  use_count    INTEGER NOT NULL DEFAULT 1,
  last_used_at INTEGER NOT NULL,
  archived_at  INTEGER,
  rev          INTEGER NOT NULL DEFAULT 1,
  updated_at   INTEGER NOT NULL,
  deleted_at   INTEGER
);
CREATE UNIQUE INDEX uq_note_text ON note_templates(text) WHERE deleted_at IS NULL;

-- 积分周期：重置不删数据，只换周期
CREATE TABLE periods (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL,                 -- "2026 秋季学期"、"11 月"
  term_key   TEXT NOT NULL,                 -- 学期归属：一学期内多次重置共用同一个 term_key
  start_at   INTEGER NOT NULL,
  end_at     INTEGER,
  status     TEXT NOT NULL CHECK (status IN ('active','archived')),
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_periods_term ON periods(term_key);
CREATE UNIQUE INDEX uq_period_active ON periods(status) WHERE status = 'active';

-- 积分流水：唯一事实表
CREATE TABLE entries (
  seq               INTEGER PRIMARY KEY AUTOINCREMENT,  -- 服务端游标，不复用，增量拉取只认它
  id                TEXT NOT NULL UNIQUE,               -- 客户端 UUIDv7，幂等键
  batch_id          TEXT NOT NULL,          -- 一次入账 = 一个批次，撤销以批次为单位
  period_id         TEXT NOT NULL REFERENCES periods(id),
  student_id        TEXT NOT NULL REFERENCES students(id),
  rule_id           TEXT,
  rule_label        TEXT,                   -- 快照，规则改名后历史不失真
  rule_delta_default INTEGER,               -- 入账时该类型的默认分，用于标出「自定义」
  delta             INTEGER NOT NULL,       -- 实际入账分值
  source            TEXT NOT NULL DEFAULT 'rule'
                    CHECK (source IN ('rule','custom')),  -- 默认分 / 自定义输入
  note              TEXT,                   -- 理由（可选）。不进查分页、不进看板
  note_template_id  TEXT,                   -- 用了哪个常用理由，仅用于统计使用频次
  capped            INTEGER NOT NULL DEFAULT 0,  -- 1 = 本条被上限压过（delta < 原请求值）
  over_cap          INTEGER NOT NULL DEFAULT 0,  -- 1 = 管理者强行突破上限
  operator_id       TEXT NOT NULL,
  operator_name     TEXT NOT NULL,          -- 快照
  identify_method   TEXT,                   -- nfc / pin / …，审计用
  occurred_at       INTEGER NOT NULL,       -- 事件发生时间（课间补录时可改）
  created_at        INTEGER NOT NULL,       -- 录入时间
  reverses_entry_id TEXT,                   -- 撤销时指向原记录的 id（不是 seq）
  reversed_at       INTEGER,                -- 被撤销时间，非空即失效（本地显示用）
  reversed_by       TEXT,                   -- 撤销人，明细里显示「已撤销 · 张老师」
  synced            INTEGER NOT NULL DEFAULT 1  -- 仅本地列：0 = 还在 outbox 里
);
CREATE INDEX idx_entries_period  ON entries(period_id, created_at DESC);
CREATE INDEX idx_entries_student ON entries(student_id, created_at DESC);
CREATE INDEX idx_entries_batch   ON entries(batch_id);   -- 撤销按批次查，别全表扫
CREATE UNIQUE INDEX uq_entries_reversal ON entries(reverses_entry_id)
  WHERE reverses_entry_id IS NOT NULL;

-- 考试：一场考试一行，只有总分，没有科目
CREATE TABLE exams (
  id           TEXT PRIMARY KEY,
  period_id    TEXT NOT NULL REFERENCES periods(id),
  name         TEXT NOT NULL,               -- "期中考试"
  full_score   REAL NOT NULL DEFAULT 750,   -- 全校统一满分 750；个别场次不同就改这一行
  exam_date    TEXT,
  imported_at  INTEGER NOT NULL,
  source_file  TEXT
);

-- 成绩：每人每场一个总分。没有 subject，也没有 normalized
CREATE TABLE exam_scores (
  exam_id     TEXT NOT NULL REFERENCES exams(id),
  student_id  TEXT NOT NULL REFERENCES students(id),
  score       REAL,                          -- 总分；缺考存 NULL，不要存 0
  absent      INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (exam_id, student_id),
  CHECK (absent = 1 OR score IS NOT NULL)    -- 非缺考必须有分
);

-- 权重方案：两个权重 + 一个口径开关
CREATE TABLE schemes (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  exam_weight  REAL NOT NULL DEFAULT 0.7,   -- 考试占比
  daily_weight REAL NOT NULL DEFAULT 0.3,   -- 平时（= 积分）占比
  normalize    INTEGER NOT NULL DEFAULT 0,  -- 0 = 原值加权（默认，班主任口径）；1 = 折百分制
  is_active    INTEGER NOT NULL DEFAULT 0,
  created_at   INTEGER NOT NULL,
  CHECK (abs(exam_weight + daily_weight - 1.0) < 1e-6)
);
-- 同时只能有一套生效，避免"到底按哪套算"的争议
CREATE UNIQUE INDEX uq_scheme_active ON schemes(is_active) WHERE is_active = 1;

-- 方案内各场考试的权重
CREATE TABLE scheme_weights (
  scheme_id TEXT NOT NULL REFERENCES schemes(id),
  exam_id   TEXT NOT NULL REFERENCES exams(id),
  weight    REAL NOT NULL CHECK (weight >= 0),
  PRIMARY KEY (scheme_id, exam_id)
);

-- 应用配置：一个班一班，键值对足够
-- 预置键：onboarding_done / seat_cols / seat_rows / lock_timeout_sec
--         sound_on / board_rotate_sec / backup_dir / last_backup_at
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- 敏感操作审计：重置、删记录、删学生、导出
CREATE TABLE audit_log (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  at       INTEGER NOT NULL,
  actor_id TEXT,
  action   TEXT NOT NULL,                   -- reset_period / delete_entry / export / delete_student
  target   TEXT,
  detail   TEXT
);
CREATE INDEX idx_audit_at ON audit_log(at DESC);

-- 备份记录：留一份可核对的凭据，而不是只看文件在不在
CREATE TABLE backups (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  at          INTEGER NOT NULL,
  path        TEXT NOT NULL,
  entry_count INTEGER NOT NULL,             -- 备份时的流水条数，事后可对数
  ok          INTEGER NOT NULL DEFAULT 1
);

-- ===== 以下两张只在本地库存在，D1 里没有 =====

-- 待推送队列：写本地成功即入队，推成功才出队
CREATE TABLE outbox (
  id        TEXT PRIMARY KEY,               -- entries.id，或 'students:<id>' 这类复合键
  kind      TEXT NOT NULL                   -- entry / reverse / student / rule / period
            CHECK (kind IN ('entry','reverse','student','rule','period')),
  payload   TEXT NOT NULL,                  -- JSON，推送时直接当请求体
  attempts  INTEGER NOT NULL DEFAULT 0,
  next_at   INTEGER NOT NULL,               -- 指数退避的下次尝试时间
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_outbox_next ON outbox(next_at);

-- 同步游标与本地状态
CREATE TABLE sync_state (
  key   TEXT PRIMARY KEY,                   -- last_seq / last_pull_at / device_id / token_key
  value TEXT NOT NULL
);
```

这三张表在前面 6.2 的清单里出现过但 DDL 漏了，补齐。`settings` 用键值对而不是宽表，是因为配置项以后一定会加，加一列就要迁移一次，不值。

**注意**：SQLite 的 `CHECK` 管不了"一组行加起来等于 1"，权重合计只能在应用层校验。所以导出前必须**再校验一次**——用户可能绕过界面直接改库，或者在两个方案之间来回切换时留下脏数据。

### 6.4 三条关键查询

**当前周期排行榜**（含撤销冲销）。注意这是**当前周期**的口径，教室大屏和查分页用它；总评要用**学期累计**，把 `e.period_id = ?1` 换成 `JOIN periods p ON p.id = e.period_id AND p.term_key = ?1`，两者差别见 8.2：

```sql
SELECT s.id, s.name, s.seat_no, s.group_name,
       COALESCE(SUM(e.delta), 0) AS points   -- 注意：不过滤 reversed_at
FROM students s
LEFT JOIN entries e
  ON e.student_id = s.id
 AND e.period_id = ?1
WHERE s.active = 1
GROUP BY s.id
ORDER BY points DESC, s.seat_no ASC;
```

**这条 SQL 不能写 `AND e.reversed_at IS NULL`，上一版写错了。** 直觉上"被撤销的不该计入"，但撤销的实现是**插入一条冲销行**：原行 +10 被标记 `reversed_at`，冲销行 −10 的 `reversed_at` 是空的。加上那个过滤条件，原行被排除、冲销行照样计入，`SUM` 变成 **−10**——撤一次，学生反而多扣 10 分。

这个错误只在"撤销过的批次"上出现，试运行一周都未必撞到，但期末一定会撞到。正确的分工是：

| 用途 | 用什么 | 为什么 |
|---|---|---|
| 算总分 | **不过滤任何行**，让冲销行自己抵消 | 冲销行有 `seq`、能跨端同步，是唯一可靠的载体 |
| 明细列表 | `WHERE reverses_entry_id IS NULL` | 否则流水里会多出一条莫名的 −10 冲销行 |
| 显示"已撤销" | `reversed_at IS NOT NULL` → 置灰 | 纯展示，不参与任何计算 |
| 找"还能撤的行" | `reversed_at IS NULL AND reverses_entry_id IS NULL` | 防止重复撤销插出"冲销的冲销" |

一句话：**`reversed_at` 是给人看的，`reverses_entry_id` 是给账本用的。** 拿前者去过滤账本，就会算错。

**撤销一整批**：

```sql
BEGIN;
-- 1) 插入冲销行：每条被撤的记录对应一条 delta 取反的新行
--    这一步才是同步的载体 —— 它会产生新的 seq，别的设备才拉得到
INSERT INTO entries
  (id, batch_id, period_id, student_id, rule_id, rule_label, delta,
   operator_id, operator_name, occurred_at, created_at, reverses_entry_id)
SELECT ?, ?, period_id, student_id, rule_id, rule_label, -delta,
       ?3, ?4, ?5, ?5, id
FROM entries
WHERE batch_id = ?1
  AND reversed_at IS NULL
  AND reverses_entry_id IS NULL;   -- 少了这句，重复点撤销会插出"冲销的冲销"

-- 2) 给原行打时间戳：只用于本地显示「已撤销 · 谁 · 几点」，不参与同步
UPDATE entries SET reversed_at = ?5, reversed_by = ?4
 WHERE batch_id = ?1
   AND reversed_at IS NULL
   AND reverses_entry_id IS NULL;

-- 3) 审计
INSERT INTO audit_log(id, actor_id, action, target, at)
VALUES (?, ?3, 'revoke_batch', ?1, ?5);
COMMIT;
```

**为什么两步都要，少一步就出错**：

| 只做第 1 步 | 只做第 2 步 |
|---|---|
| 总分对了，但明细里原始记录还是"有效"的，老师看不出这条被撤过 | **另一台设备永远不知道撤销发生了**——增量拉取只认 `seq`，`UPDATE` 不产生新 `seq` |

这是只追加模型配增量同步时最容易写错的一处：**冲销行是同步载体，`reversed_at` 只是本地显示标记**。`reversed_at` 丢了可以重建（扫一遍 `reverses_entry_id`），冲销行丢了就是真丢。

事务里这两步的先后顺序也有讲究：**先插冲销行，后打标记**。反过来的话，如果第二条语句失败回滚，冲销行没插进去而标记也回滚了，没问题；但若先打标记、第二条插冲销时因为唯一索引冲突失败，就会留下一批"标记为已撤销、但没有冲销行"的记录，总分虚高，而且要手工排查。先插后标，失败时最多是"冲销行存在但原行没打标记"，那只是显示问题，账是平的。

**加权排名**（在 SQL 里只取原料，折算放 C#，因为公式要能改）：

```sql
SELECT s.id, s.name, s.seat_no,
       COALESCE(SUM(e.delta), 0) AS points   -- 同上：不过滤 reversed_at
FROM students s
LEFT JOIN entries e ON e.student_id = s.id AND e.period_id = ?1
WHERE s.active = 1
GROUP BY s.id;

SELECT es.student_id, ex.id, es.score, ex.full_score, w.weight
FROM exam_scores es
JOIN exams ex         ON ex.id = es.exam_id
LEFT JOIN scheme_weights w ON w.exam_id = ex.id AND w.scheme_id = ?2
WHERE ex.period_id = ?1;
```

三条要点，都是这一版新定的：

- **不查 `normalized`，因为它不存在了。** 百分制折算放 C# 里现算（`score / full_score * 100`），满分改了立刻生效，不用重算一遍历史。
- **缺考行也取，`absent` 交给上层判断。** 缺考不是"没有这行"，是"这行没分但占位"——权重再分配要靠它算剩余权重，SQL 里 `WHERE absent = 0` 会把这条信息丢在数据库里。
- **积分不过滤 `reversed_at`**（上一段已解释），**成绩按 `period_id` 过滤**。两者口径不同是故意的：积分是流水，成绩是快照。

### 6.5 撤回：一个动作，七种情况

"撤销"在单机版里只是一个按钮。到了双端 + 只追加，它分裂成七种情况，处理方式完全不同——**这七种里有三种是学生真的会踩到、而代码里最容易漏的**。

| # | 情况 | 处理 | 谁在什么时限内能做 |
|---|---|---|---|
| 1 | 刚入账，记录还在本机 outbox 里没推出去 | **直接从本地删掉，从 outbox 移除**，不插冲销行 | 操作者本人，5 秒内 |
| 2 | 已推送成功，同一台设备 | 插冲销行 + 打 `reversed_at` | 班委本人 5 分钟内的批次；班主任任意批次 |
| 3 | 另一台设备记的 | 同上，但权限收紧：班委不行，班主任可以 | 班主任 / 副班主任 |
| 4 | 连续确认了两次，同一批人同一类型 | **两个独立批次**，各自可撤；撤销条只显示最近一次 | 同 #2 |
| 5 | 撤错了，想恢复 | **不做"撤销的撤销"**，给一个「重做」，按原类型原分值重记一条 | 任何人 |
| 6 | 周期已重置、归档了 | **不能撤**。只能在新周期补记一条，备注写「补记 · 原 10-15 回答问题」 | 班主任 |
| 7 | 删了学生 / 改了名单 / 调了权重 | 走 `deleted_at` 与 `rev`，30 天内可从「回收站」恢复；重置不可撤 | 班主任 |

**#1 是最容易写错的一条。** 本地有一条 `synced = 0` 的记录，老师立刻点了撤销。如果照常规插一条冲销行并推送，Worker 会收到一条 `reverses_entry_id` 指向云端根本不存在的记录的冲销，然后：

- 要么 500（外键/校验失败），outbox 卡死，后续所有记录跟着堵；
- 要么写进去，云端凭空多一条 +10 的冲销行，把别人的分改了。

所以判断顺序必须是：**先看它在不在 outbox，在就直接清掉，等于这事没发生过**。判据不能只用 `synced` 标志——推送请求已经发出去、响应还没回来时，`synced` 仍是 0，但云端可能已经写入了。这条要给 30 秒的宽限：`created_at` 在 30 秒内且 outbox 里还在，才允许"物理删除"；超过 30 秒一律走冲销行，宁可多一条记录，也不要把分数算错。

**#5 为什么不做"撤销的撤销"。** 技术上可以做（再插一条冲销，指向冲销行），但代价是明细里出现三层嵌套：`+10 → −10 → +10`，一个月后没人看得懂。而且 `uq_entries_reversal` 这个唯一索引会逼你维护一条链，链越长越容易出环。所以恢复用**重做**：一条干净的新记录，`operator` 是现在的人，时间是现在的时间，备注自动加「重做」。老师要的是分回来，不是要一段可回溯的操作史。

**#4 这一版简化了，因为确认条把老前提消掉了。** 上一版写"200 ms 内同一学生同一类型连点，合并成一条 +30"，那是"单击直接入账"时代的设计——现在第一次点击只弹确认条，连点根本产生不了三条记录。所以规则改成一句话：**一次确认 = 一个批次 = 一个撤销单位。**

老师连点三次确认，就是三个批次，撤销条显示最后一个；要全撤，去明细里按时间段批量撤（6.5 表 #2 的"任意批次"）。这比合并规则好解释得多——**老师脑子里的"我刚才点了三次"，就该对应账本上的三条**，而不是一条 +30。

一次操作里点了两个不同类型（回答问题 +10、黑板演题 +100），是两次确认、两个批次。上一版说"同一 batch_id 撤批就两条都撤"，这一版不这么做了：**每个批次只包含一次确认的内容**，语义最清楚，也不会出现"我只想撤演题那下、结果发言也被撤了"。

**撤销的权限边界**，和记分不一样：

| 操作 | 大屏端 | 电脑端 |
|---|---|---|
| 撤自己 5 分钟内的批次 | 不弹密码 | 免密 |
| 撤别人的批次 | **弹管理模式密码** | 免密，但写审计 |
| 撤跨天的记录 | 弹密码 | 免密 |
| 撤已归档周期的记录 | 不允许 | 不允许 |

"撤自己的不用密码、撤别人的要密码"这条看着别扭，但它精确对上了密码在这套系统里的定位——**它不是身份认证，是防误操作闸**。班委撤自己刚记错的那一条，是修正；撤别人记的，是覆盖他人的工作，该确认一次。

**界面上的三个必做项**：

1. **撤销后分数不能"悄悄变"**。卡片要有一次明确的回滚动画 + 短暂显示 `−2 已撤销`（砖红色，1.5 秒）。学生正盯着屏幕，分无声无息地掉了，他只会认为系统坏了或者老师偏心。
2. **明细里已撤销的记录保留并置灰**，标注「已撤销 · 张老师 14:35」。删掉它，老师会怀疑数据丢了；留着它，才叫账本。
3. **撤销也要进"待同步"计数**。它和加分走同一个 outbox，断网时界面必须显示"待同步 1 条"。少了这一条，老师会以为已经撤了，第二天发现分还在——而这时候原始记录可能已经被别的设备拉走了，解释起来极其麻烦。

**跨端同步的时延要说清楚**：教室撤了一条，办公室那台最多 4 秒后才看到。如果班主任正对着办公室的屏幕核对，会看到"教室说撤了、我这儿还在"。设置项里有一行「最后同步：2 秒前」，靠这个解释，不要靠猜。

## 七、成绩导入与加权排名

这一章**整章只在电脑端存在**（原因见 9.2）。它会被家长拿着问，所以成败不在算法，在于"能不能一句话解释清楚"。

先说清这一版砍掉了什么：**没有科目、没有单科分析、没有列映射向导。** 学校给的成绩单长什么样你比我知道得清楚——一堆合并单元格、表头在三行之后、底下还挂着"班平均""年级排名"。但我们要的只有两列：**姓名、总分**。剩下的全是噪声，导入器的任务是把噪声扔干净，而不是把所有列都搬进来。

### 7.1 导入：三步，只认姓名和总分

```
选文件 → 认两列 → 预览入库
```

**第一步：选文件。** 支持 `.xlsx` / `.xlsm` / `.xls` / `.csv`，拖进来或点选。

学校的成绩单十有八九是旧格式，而且经常是"`.xlsx` 扩展名的 `.xls`"——用 Excel 另存时顺手改了扩展名，文件头没变。所以**判断格式看文件头，不看扩展名**：

| 文件头（前 4 字节） | 真实格式 |
|---|---|
| `50 4B 03 04`（`PK..`） | xlsx / xlsm（zip 容器） |
| `D0 CF 11 E0` | xls（OLE 复合文档） |

读取统一走 **NPOI**（xlsx / xls 两种都能读），写入导出继续用 ClosedXML。不要试图用 ClosedXML 打开 `.xls`——它会抛一个和格式毫无关系的异常，用户看到的是"未知错误"。

**CSV 单独走一条路**（`CsvHelper` 或手写解析，别塞给 NPOI）：学校导出的 CSV 十有八九是 **GBK 编码**，按 UTF-8 读出来全是乱码。判断顺序：有 BOM 就按 BOM；没有 BOM 先试**严格 UTF-8**（`new UTF8Encoding(false, true)`，解码失败会抛异常），失败再按 `GB18030` 读。**不能反过来**——GBK 几乎能「读通」任何字节序列，先试 GBK 的话你永远发现不了自己读错了，只会得到一屏乱码和一堆匹配不上的姓名。

**多 sheet 的情况默认读第一个非空 sheet**，右上角给一个下拉能切。教务系统导出的表经常第一页是"说明"、第二页才是数据，静默读第一个 sheet 会读到一片空白。

**第二步：认两列。** 只有两个下拉，其余全部忽略：

```
┌────────────────────────────────────────────────┐
│ 文件：高三2班期中成绩.xlsx   [换文件]            │
│ Sheet：[Sheet2 ▾]                              │
│                                                │
│ 姓名列 [ B ▾ ]     总分列 [ F ▾ ]               │
│ 满分   [ 750 ]     考试名称 [期中考试]  日期[11-08]│
│                                                │
│ 预览（前 5 行）：                                │
│  B          F                                   │
│  王小明     682                                 │
│  李思远     594                                 │
└────────────────────────────────────────────────┘
```

自动猜列，但永远让用户确认。**不要做全自动导入**——猜错一次，班主任就再也不信这个功能。

猜的规则只有两条，够用：

1. **表头行**：从第 1 行往下扫 10 行，找同时含"姓名"（或"学生"）的单元格所在行。找不到就退化成"第 1 行"。
2. **总分列**：在这行里找表头匹配 `总分|合计|总计|总成绩|成绩` 的列，取最右一个。**"成绩"这个词要排在最后**——很多表里"语文成绩""数学成绩"都含这个词，总分列通常叫"总分"。

**第三步：预览入库。** 这张表是给人看的，所以每一行都要有明确归属：

| 姓名 | 分数 | 匹配 | 状态 |
|---|---|---|---|
| 王小明 | 682 | 王小明 · 3 排 2 座 | ✓ |
| 李思远 | 594 | 李思远 · 3 排 3 座 | ✓ |
| 王 芳 | 631 | 王芳 · 5 排 1 座 | ✓ 已去空格 |
| 张伟 | — | — | 缺考 |
| 班平均 | 598 | — | ✗ 非学生行，已忽略 |
| 陈默 | 712 | 两人同名 | ⚠ 请选择 |

底部汇总：「可导入 46 人，缺考 2 人，忽略 3 行（汇总行），2 行待处理」。

**这张表要说真话的地方在"忽略 3 行"**——汇总行是静默跳过的，但如果不说，老师会以为导入器吞了数据。凡是做了决定的地方，都要在界面上留一行字。

成绩单里真正会咬人的六种情况，全部在这一步处理掉：

| 情况 | 处理 |
|---|---|
| 底部汇总行（班平均 / 年级排名 / 最高分 / 最低分） | 姓名匹配不上任何学生 → 标"非学生行"自动忽略，但计入"忽略 N 行" |
| 姓名带空格（两字名排版成"王 芳"）、全角空格、`U+00A0` | 统一规范化：去所有空白字符、全角转半角、繁转简，再匹配 |
| 同名两人 | 列出候选（带座位号）让人点选，**不自动选第一个** |
| 分数是文本：`缺考`、`-`、`/`、`—`、空 | 一律记 `absent = 1`、`score = NULL`，不记 0 |
| 分数超过满分（如 782 / 750） | 标红单行提示，允许强导（有的学校有加分项），但要求确认 |
| 名单里没有这个人 | 两个按钮：「加入名单」/「忽略此行」。**转学生第一次出现就在这一步进系统** |

**不带学号也能匹配，这是刻意的。** 你说了只取姓名和总分，所以匹配只靠姓名。学号在成绩单里经常被 Excel 吃掉前导零、或者干脆没有，靠它反而更脆。

**入库是整批一个事务。** 同一场考试重复导入 → 按 `(exam_id, student_id)` 主键覆盖，不新建第二场。同名考试已存在时给一句「这场考试已有 48 条成绩，导入将覆盖」，默认按钮是**取消**——覆盖成绩是不可撤销的操作，值得多点一下。

```sql
-- 幂等写法：重复导入同一场，覆盖而不是翻倍
INSERT INTO exam_scores (exam_id, student_id, score, absent)
VALUES (?1, ?2, ?3, ?4)
ON CONFLICT(exam_id, student_id) DO UPDATE
  SET score = excluded.score, absent = excluded.absent;
```

### 7.2 平时分就是积分，总评按班主任的口径算

#### 平时分

```
平时分 ≡ 学期累计积分
```

**这里的"累计"是整学期累计（跨周期相加），不是当前周期。** 积分可以按月清零让榜单重新开始，总评不能按月算——10 月底清零一次，11 月的期中考试就会对着一个空积分算总评。两个口径的 SQL 和界面区分写在 8.2。

**这是同一个数，不是两个数。** 数据库里没有"平时分"这个字段，界面上叫"平时分"的地方直接读 `SUM(delta)`。好处很实在：不存在"积分改了平时分没跟着变"这类 bug，也不存在两列数字对不上被家长抓住。

#### 总评：默认按原值加权，不做归一

这是班主任定的口径，我照做。默认就是最朴素的那一条：

```
总评 = 考试总分 × 考试权重 + 学期累计积分 × 平时权重
```

考试是 750 制，积分是四位数，两个原值直接加权。**不折百分制、不除以最高分、不加任何系数。**

**这条口径的代价必须写在明面上，因为它不是"换个刻度"那么简单。** 同样是 70/30，用你班上会出现的数（考试均分 600、积分均 2400）：

| | 考试贡献 | 积分贡献 | 实际占比 |
|---|---|---|---|
| 名义权重 | 70% | 30% | —（它只是乘数） |
| 实际数值 | 600 × 0.7 = 420 | 2400 × 0.3 = 720 | **37 : 63** |

名义 30% 的积分，实际贡献 63%。**这是原值加权的必然结果**——两个量的量纲不同，权重就不是它看起来的那个比例。班主任要的可能正是这个效果（积分压过考试），那就对了；但如果他以为自己在调"三七开"，那就要让他看见真实的数。

所以设置页的滑块下面加一行**实时换算，不是提醒，是如实显示**：

> 名义权重 70 : 30　→　按全班平均实际影响 **37 : 63**（考试均分 600、积分均 2400）

这行字不改变任何计算，只是把"名义"和"实际"的差摆出来。老师看到 37:63 觉得不对，自己会去调滑块；觉得对，就继续。**决定权在他，知情权也给他。**

#### 归一：留作选项，默认关

设置页里有一个开关「把总评折算成百分制（0–100）」，**出厂关闭**。打开后：

```
考试百分制 = 考试总分 ÷ 该场满分 × 100
平时百分制 = 本人积分 ÷ 班内最高积分 × 100

总评 = 考试百分制 × 考试权重 + 平时百分制 × 平时权重
```

两个分母都是现成的，不需要老师填任何参数。但**它会让名次变化**，这一点必须提前说清楚，否则老师打开开关后发现排名变了，会以为系统算错了：

| 学生 | 考试 | 积分 | 不归一（默认） | 名次 | 归一（可选） | 名次 |
|---|---|---|---|---|---|---|
| 李思远 | 594 | 3000 | 1315.8 | **1** | 85.4 | 2 |
| 王小明 | 682 | 2400 | 1197.4 | 2 | **87.7** | **1** |
| 张雨欣 | 645 | 900 | 721.5 | 3 | 69.2 | 3 |
| 陈默 | 712 | 120 | 534.4 | 4 | 67.6 | 4 |

差别在头两名：**不归一时积分满分的人赢，归一后考试最高的人赢。** 这不是 bug，是两种口径在问两个不同的问题——"谁为班级付出更多"还是"谁各方面都靠前"。

所以开关文案不能写"显示成百分制"，要写清后果：

> ☐ **总评折算成百分制（0–100）**
> 　打开后，考试和积分各按满分折算再加权。**会让部分学生名次变化**（积分高但考试一般的学生会下沉）。
> 　当前：关闭 · 总评为原值加权和，不是百分制。

#### 两种口径都要在导出表里标清楚

这是最容易出事的地方：同一份「总排名」表，如果不说清口径，一个月后没人知道那个 1315.8 是什么单位。

| 口径 | 表头写什么 | 参数说明页写什么 |
|---|---|---|
| 默认（不归一） | **总评（加权和，非百分制）** | 考试总分 × 70% + 积分 × 30%，两者均为原值 |
| 归一（可选） | 总评（百分制） | 考试 ÷ 满分 × 100 × 70% + 积分 ÷ 班内最高 3000 × 100 × 30% |

不归一时还要加一句提示，在表格上方或页脚：

> 本表总评为加权和，不是百分制分数，不可与考试成绩直接比较；同一表内排名有效。

**"同一表内排名有效"这句很重要。** 原值加权和虽然数值大得吓人，但排序是完全正确的——它只是不能拿去上报、不能跟别的班比、不能跟去年的自己比。把这三条边界写清楚，这个数字就可以用。

#### 三条不能破的底线

1. **积分不封顶、不保底、可加可扣。** 落到实现上就是 `SUM(delta)` 不做任何 clamp。允许负分，允许超过任何"看起来合理"的数。负分会真实出现在榜单和导出表里。
2. **总评不截断。** 不归一时总评可能是 1400 也可能是 −80；归一后平时百分制上限是 100，但考试百分制可能因加分超 100。**一律不要 `Math.Clamp(0, 100)`**——截断会让两个不同的学生变成同分，排名直接失真。
3. **保留一位小数。** 48 个人里有三四个会连着两位相同，一位小数够区分；保留两位会让表看起来像精密仪器，反而招来"这 0.03 分是怎么来的"的追问。

**积分通胀还是要盯。** 不封顶意味着班委一周多发几十也没人拦。对策不是加规则，是让它可见：「行为分布看板」按项目统计发放次数与总分，某个项目一周发了 200 次，一眼就看出来。**数据透明比规则约束有效。**

### 7.3 权重：两个滑块 + 一张表

两种口径共用同一套权重，区别只在最后一步怎么合：

```
默认（不归一）
  总评 = 考试总分加权和 × We  +  学期累计积分 × Wd

可选（归一，默认关）
  总评 = 考试百分制 × We      +  平时百分制 × Wd

其中
  考试总分加权和 = Σ(第 i 场总分 × wi)                  Σwi = 100%，原值（750 制）
  考试百分制     = Σ(第 i 场总分 ÷ 该场满分 × 100 × wi)  只有归一/百分制时才需要
```

**第一层（考试 vs 平时）**：两个联动滑块，拖一个另一个自动补足，默认 70 / 30。滑块下面必须挂 7.2 那行"名义 vs 实际影响"的实时换算——这是唯一能让老师看懂自己到底调了什么的东西。

**第二层（各场考试之间）**：一场考试一行，没有科目维度：

| 考试 | 日期 | 满分 | 权重 |
|---|---|---|---|
| 第一次月考 | 10-12 | 750 | 20% |
| 期中考试 | 11-08 | 750 | 30% |
| 第二次月考 | 12-10 | 750 | 20% |
| 期末考试 | 01-15 | 750 | 30% |
| **合计** | | | **100%** ✓ |

四条规则：

1. **合计必须 100%。** 不等于时导出按钮变灰、数字标红，旁边给「自动配平」（按现有比例缩放到 100）。**这里叫「配平」不叫「归一」**——归一在这个方案里已经专指总评折百分制那个开关，两个词混用会让人以为动的是同一件事。滑块适合摸方向，数字输入适合精确到 1%——老师会说"期末占 40%"，不会说"拖到 40% 左右"。
2. **满分默认 750，逐场可改。** 有的学校月考按 6 科 750、期中按 9 科 1050，就把那一场的满分改成 1050。**注意：默认口径（不归一）下满分只是个标签，不参与计算**——原值加权时 1050 分的考试天然比 750 分的重，这本来就是原值口径的性质。只有打开百分制开关，满分才真正参与折算。这一点要在界面上写清，否则老师改完满分发现总评没变，会以为坏了。**不要在校级层面搞"统一满分"**，那是给自己找麻烦。
3. **缺考怎么算必须让用户选**，这是家长会最容易吵起来的地方：

| 处理方式 | 做法 | 适用 |
|---|---|---|
| **权重再分配**（默认） | 缺考那场不计，其权重按比例摊给其余场次 | 病假、免修 |
| 记 0 分 | 直接按 0 计入 | 无故缺考 |
| 全班均值替代 | 用该场全班平均分替代 | 转学生插班 |

缺考的学生在表里显示「缺考 · 按权重再分配」，不要留空——留空会让班主任以为数据没导进来。

4. **实时预览才是重点。** 改权重的目的通常是"看看前十名会不会乱"，所以拖滑块时表格必须同步重排，并给一句结论：

> 权重调整后，前 10 名中 2 人位次变化（李明 ↑3，王芳 ↓2）

这句话比任何图表都有用——它把"我在调参数"变成"我在看后果"。

**只有一场考试时，第二层自动隐藏。** 学期初刚考完一次月考，那张权重表只有一个 100%，占地方且让人困惑。界面上少一个控件，就少一个"这是干什么的"。

### 7.4 导出

一次导出 4 个工作表（ClosedXML）：

| 工作表 | 内容 | 用途 |
|---|---|---|
| **总排名** | 名次、姓名、座位、考试总分、**平时分（= 积分）**、**总评（加权和，非百分制）** | 直接打印张贴 |
| **成绩明细** | 各场考试原始总分、该场满分、该场权重、缺考处理方式 | 家长会逐项解释 |
| **积分流水** | 日期、学生、项目、分值、记录人、备注 | 有争议时追溯 |
| **参数说明** | 权重、满分、口径（归一/不归一）、归一基准、公式原文、导出时间、导出人 | **自证清白** |

**如果打开了百分制开关，第一张表和第四张表的措辞要跟着变**：表头写「总评（百分制）」，参数说明写归一口径。一份表里不能同时出现两种口径的数。

**"平时分"和"积分"只留一列。** 它们本来就是同一个数，并排出现两列一模一样的数字，第一个问题就是"为什么重复"。表头写「平时分（积分）」，一列解决。

第四张表最容易被忽略，但最重要。里面要写清楚到能复算的程度：

> 平时分 = 学期累计积分（同一学期内跨周期相加，不封顶、不保底、可加可扣）；
> 总评 = 考试总分加权和 × 70% + 学期累计积分 × 30%（**原值加权，未折百分制**）；
> 考试总分加权和 = 月考 594 × 20% + 期中 682 × 30% + 月考 640 × 20% + 期末 700 × 30%；
> 缺考按权重再分配；统计周期 2026-09-01 至 2027-01-20；导出时间 2027-01-21 14:03；导出人 张老师。
>
> **本表总评是加权和，不是百分制分数，不可与考试分直接比较；同一表内排名有效。**
> 若需百分制，打开「总评折算成百分制」后重新导出（会改变部分学生名次）。

有了这一页，任何质疑都能当场对上账。**没有这一页，Excel 表就只是一堆数字，谁都能说"你这算错了"。**

不归一的口径尤其需要这一页：**一张表上出现"总评 1315.8"这种数，不给解释就等于让人怀疑软件坏了。** 那一行"加权和，非百分制"不是免责声明，是这张表的说明书。

代码骨架：

```csharp
public byte[] BuildWorkbook(RankingResult r, Scheme s)
{
    using var wb = new XLWorkbook();

    var ws = wb.Worksheets.Add("总排名");
    ws.Cell(1, 1).Value = "名次";
    ws.Cell(1, 2).Value = "姓名";
    // 平时分与积分同源，只出一列
    ws.Cell(1, 5).Value = "平时分（积分）";
    // 表头跟着口径走，不写死
    ws.Cell(1, 6).Value = s.Normalize ? "总评（百分制）" : "总评（加权和，非百分制）";
    // …表头与数据…

    ws.SheetView.FreezeRows(1);
    ws.RangeUsed().SetAutoFilter();
    ws.Columns().AdjustToContents();

    // 参数说明页：公式原文和归一基准都写进去
    var info = wb.Worksheets.Add("参数说明");
    info.Cell(1, 1).Value = "折算公式";
    info.Cell(1, 2).Value = s.FormulaText;   // 由 Scheme 现算，不写死字符串
    info.Cell(2, 1).Value = "总评口径";
    info.Cell(2, 2).Value = s.Normalize ? "百分制（已归一）" : "原值加权和（未归一）";
    info.Cell(3, 1).Value = "归一基准";
    info.Cell(3, 2).Value = s.Normalize
        ? $"班内最高 {r.MaxPoints} 分（{r.MaxPointsWho}）"
        : "—（未归一）";
    info.Column(2).Width = 80;

    using var ms = new MemoryStream();
    wb.SaveAs(ms);
    return ms.ToArray();
}
```

两个 ClosedXML 的坑：**学号如果需要保留，必须设成文本格式**否则 `20260001` 会变科学计数法（这一版不导学号，但积分流水页可能带）；**公式不会自动算**，ClosedXML 只写公式不写缓存值，用 Excel 打开才重算——所以汇总值要在 C# 里算好写死，不要依赖公式。

## 八、周期与重置

"重置加分"如果实现成 `DELETE FROM entries`，就是一次不可恢复的灾难。正确的模型是**周期（period）**：

```
重置 = 关闭当前周期（status = archived）+ 新建一个 active 周期
```

`entries` 一行不删，通过 `period_id` 归属到不同周期。排行榜只统计当前 active 周期。

### 8.1 重置时的七件事

**第零步必须先做：向云端申请重置令牌。** 这是两端架构下唯一真正危险的操作——教室电脑上点了重置，办公室电脑正在导成绩，两边对"当前周期"的理解会分叉，结果是一部分记录落进已归档的周期，找都找不回来。

做法：`POST /periods/reset` 申请令牌，Worker 把班级标记为 `resetting`，这期间两端拒绝写入非重置类操作（记分按钮变灰并提示「正在归档」）。归档提交后释放标记。令牌**出厂 90 秒，每 45 秒续期一次**——固定 2 分钟是不够的：50 人一学期六万条记录写 xlsx 加数据库副本，慢机器上要几十秒，加上老师中途犹豫一下，很容易过点。续期只在归档真正进行时发，人走了不续，90 秒后自动释放，不会把班级永久锁死。这比"最后写入胜"安全，也比分布式锁便宜——它只需要一个字段和两个检查点。

令牌到手后，一个事务做完六件事：

1. 检查是否有未完成的撤销（有就提示先处理）。
2. **自动生成归档包**：`归档-2026秋季学期-20270120.xlsx`（含四张表）+ 数据库副本，存到备份目录。
3. 当前周期置为 `archived`。
4. 新建周期，命名默认「2027 春季学期」，可改。**重置积分沿用原 `term_key`，重置学期新生成一个**——这一行决定总评是连续的还是断开的，见 8.2。
5. 写 `audit_log`（谁、几点、归档到哪）。
6. 界面提示「已归档 1,284 条记录，可在『历史周期』查看和导出」。
7. **清掉所有挂在周期上的派生状态**：周期累计封顶的计数、榜单缓存、"本周期已发放 N 分"的统计、看板的轮播位置。这几样任何一项漏清，新学期第一天的界面就是错的——最常见的是"早读背课文"在新学期第一次点击就显示"已达上限"，因为上学期的 50 分还记在内存里。

### 8.2 两种重置粒度

| 类型 | 影响范围 | 使用场景 | 确认方式 |
|---|---|---|---|
| **重置积分** | 只新建积分周期（`term_key` 不变），考试成绩保留 | 每月清零榜单，让学生重新开始 | 普通确认框 |
| **重置学期** | 积分 + 考试 + 名单全部归档，`term_key` 新建 | 升年级、换班 | **长按 3 秒** + 输入"确认重置" |

第二种一定要做到"很麻烦才能点下去"。这是唯一会造成大面积数据不可见的操作。

#### 积分可以按月清，总评不能按月算

这是"重置"和"总评"之间唯一一处必须提前想清楚的地方，不做会在期末炸出来：

- **积分榜**按当前周期算（`period_id = 当前`），每月清零后大家好重新开始，这是对的。
- **总评**必须按**学期**算。一场期中考试是 11 月，如果积分在 10 月底清零过，用"当前周期积分"去算总评，等于把一个半月的班级表现凭空抹掉。

所以 `periods.term_key` 这一列不是可选的：**同一学期内无论重置几次，`term_key` 都不变**；总评按 `WHERE term_key = ?` 把整学期的流水加起来。重置学期才换 `term_key`。

代价是每个查询要明确自己算的是哪个口径，写的时候容易混。两个口径在这里都写出来，照着抄：

```sql
-- 积分榜（当前周期）：教室大屏用这个
SELECT student_id, SUM(delta) AS pts FROM entries
WHERE period_id = (SELECT id FROM periods WHERE status = 'active')
GROUP BY student_id;

-- 平时分（整学期）：总评用这个，跨周期相加
SELECT e.student_id, SUM(e.delta) AS pts
FROM entries e JOIN periods p ON p.id = e.period_id
WHERE p.term_key = (SELECT term_key FROM periods WHERE status = 'active')
GROUP BY e.student_id;
```

**两个数字会不一样，而且都对。** 界面上必须分开标：「本月积分」和「学期累计」，不要都叫"积分"。这是最容易让老师以为算错的地方。

### 8.3 历史周期

设置页留一个「历史周期」入口，列出所有 `archived` 周期：名称、时间范围、记录数、归档文件路径，可以随时查看榜单、导出 xlsx。**这才是"重置"能被接受的前提——班主任要知道旧数据还在。**

## 九、界面

### 9.1 首次启动：欢迎页（五步，五分钟加出第一条分）

从"装好"到"加出第一条分"如果超过五分钟，这套软件在老师那里就死在这一步了。所以欢迎页不是产品介绍页，是**配置向导**：每一步都预填好默认值，赶时间就一路「下一步」，事后在设置页逐项改回来。

| 步 | 内容 | 默认值 | 可否跳过 |
|---|---|---|---|
| 1 班级 | 班级名、学期起止 | 学期按当前日期自动填 | 不可（班级名是唯一必填项） |
| 2 名单 | **粘贴一列姓名** / 逐个输入 / 稍后再说 | 空名单，座位布局预置 8×6 | 可 |
| 3 分值 | 三条预设（回答问题 +10、早读 +50 上限 50、演题 +100），就地改分值或删掉 | 三项全启用 | 可（用当前三条） |
| 4 建班与认人 | **创建班级**（生成 6 位班级码）；设**管理模式密码**；生成恢复码；登记班委卡 | 6 位密码 + 一张恢复码 | 不可，但走「跳过全部」时延后到第一次管理操作强制补设 |
| 5 自检 | 真实窗口下的 48 人排版 + 试加一条分（含确认条），再撤销 | — | 不可单独跳过（它只是一次点击） |

**向导第 4 步必须联网，所以第 1 步就要检查。** 建班、设密码、生成恢复码全在云端完成，没有网络走不通。最差的实现是让老师填完四步、点「完成」时才报错——所以第 1 步点「下一步」时先 ping 一次 Worker，不通就当场说：「需要联网才能创建班级，请检查 Wi-Fi」，并给「重试」和「稍后配置」两个出口。**「稍后配置」进的是只读演示态**（用占位名单看界面），不是让人在空库里开始记分。

**第 2 步为什么在大屏端只做「粘贴」，不做 Excel 导入**：完整的 Excel 导入要选文件、映射列、处理合并单元格和前导零，那是坐着用键鼠干的活——它归电脑端（见 7.1）。一体机上只需要"先有名字能记分"：老师在家里把名单复制到微信文件传输助手，到教室粘贴一列姓名，10 秒完事。**这两个入口不是重复，是两种场合**：一个是"开学第一天，把系统跑起来"，一个是"名单要带上学号、座位、分组"。

**第 5 步是整个向导存在的唯一理由。** 它在老师还愿意折腾的时候，把四个问题一次暴露出来：48 人能不能放下、手指点得准不准、那排类型按钮够不够宽、确认条会不会挡住卡片。这里渲染的是**真实的记分台控件**，不是示意图——名单已经在了，直接排出来，底部给一行判词：

> 当前窗口 8 列 × 6 行，48 人一屏放下。把窗口拖窄会自动变 7 列并出现滚动条——**长按 0.4 秒再拖才是框选**，直接滑是滚动。按任意卡片试试，最后记得点「确定」。

判词里的数字必须**按当前窗口实算**，不能写死"8 列 6 行"——老师可能已经把窗口拖小了，写死会让他以为软件坏了。

**如果第 2 步选了"稍后再说"，第 5 步用 48 个临时占位卡片**（"学生 01"…"学生 48"，只在内存里，不写库）。判词换成：「这是 48 个演示卡片，真实名单到电脑端导入后，排版和这个一样。」不做这一步的话，跳过名单的人会卡在第 5 步，面对一个空网格，然后关掉向导——而自检恰恰是向导唯一的价值。

试加的那一分**只在内存里生效，不写库**——这和下面第 2 条是同一个规则。分数、动画、"已给 王小明 +10 撤销"的提示条全部走真实控件的真实代码路径，唯独不碰数据库。好处是零污染：退出第 5 步立刻复原，流水里不会留一条"测试"记录，期末导出时也不用跟人解释它是谁加的。

四个工程细节，每个都能省掉一轮返工：

1. **向导窗口用普通窗口，不要全屏。** 全屏向导在一体机上会让人怀疑"这软件是不是要接管电脑"，而且老师常常要切到 Excel 去抄名单。
2. **「完成」之前一个字节都不写库。** 所有选择先攒在一个内存对象里，最后一次性落盘。否则用户中途关掉向导，库里会留下半截配置——最难查的那种脏数据。
3. **允许「跳过全部，用默认设置」，但它绕过的是第 1、2、3 步，不是第 4 步。** 跳过后第一次进管理模式时强制补设密码，设完才允许改名单。宁可打断一次，也不能出现"谁都能清空学期数据"的状态。
4. **第 3 步就地改分值，不要跳去设置页。** 每行一个 `−/+` 和数字框，改完还在原地。跳页会让一半人在第三步就放弃。

#### 两端首次使用不一样

| | 大屏端（教室一体机） | 电脑端（办公室） |
|---|---|---|
| 谁先装 | 先装这台，因为它先产生数据 | 后装，要靠它把数据拉下来 |
| 第 4 步做什么 | 设**管理模式密码**，生成恢复码，登记班委卡 | 输入班级码 + 那个密码，完成**设备配对**，之后永久免密 |
| 向导几步 | 五步（建班级、名单、分值、密码、自检） | **两步**：配对 + 拉取 + 自检。班级名、名单、分值全部从云端拉下来，不重复问 |
| 之后每次打开 | 班委刷卡记分；班主任只在进管理模式时输密码 | 直接进，不再问任何密码 |
| 换人怎么办 | 30 秒闲置自动回看板，下一个人必须重新刷卡 | 换 Windows 账户登录即失效，要求重新配对 |

**恢复码只在大屏端生成一次，但两端都要用。** 它是"密码忘了 / 电脑换了 / 重装系统"时唯一能拿回 owner 权限的东西，见 2.7。向导里必须让它可见可抄，并顺手提供"打印一张恢复卡"（打印功能见 9.7，这是它第一个用途）。

#### 预设：就你给的三项，不加别的

初始数据里只有三行，不多加一条：

| 类型 | 默认分 | 上限 | 排序 |
|---|---|---|---|
| 回答问题 | +10 | 无 | 10 |
| 早读检查背课文 | **+50** | **50（单次）** | 20 |
| 课上黑板演题 | +100 | 无 | 30 |

**上一版我按"频率对齐"补了作业优秀 +20、考试进步 +50、迟到 −10 等五条，这一版全删了。** 理由是你说的那句"不要乱加"——那五个分是我拍的，不是你们班的班规。预设一旦多了，老师第一件事就是逐条删，比逐条加更烦；而且删到一半的模板，比三个准确的项目更难用。

空位就留空。类型列表最后一行常驻「＋ 新建加分项」，点开是名称 + 分值 + 图标 + 上限四个字段，30 秒能加一条。**三个能用的项目 + 一个显眼的"新建"，比八个半对不对的项目好。**

班级实际班规到手后，有两条路：告诉我，我改成预设种子；或者老师自己在设置页加——两条都行，后者不需要重装。

**这三项的量级是这样配的**（改分值前先看一眼，别只盯单个数字）：

| 类型 | 一学期次数 | 一学期总分 | 角色 |
|---|---|---|---|
| 回答问题 | 100–300 | 1000–3000 | 主力，决定榜单中段 |
| 早读背课文 | 20–60 | 1000–3000 | 主力，决定榜单上段 |
| 课上黑板演题 | 10–30 | 1000–3000 | 高光项，低频高额 |

三项量级相当，这是有意的：**没有哪一项能单独决定榜单**，学生得在不同维度都参与。若某一项一学期的量级超过全班总分的 40%，就该降分或降频——这条判断标准比"10 分大不大"有用。

两条选值时别违背的原则：

- **高频低分、低频高分。** 这是唯一能同时容纳 +10 和 +100 的规则。反过来（高频高分）会让一次普通发言抵掉一次演题，分值失去区分能力。
- **扣分项你还没给，所以预设里没有。** 真要加时，负分绝对值别超过同类正分的 1.5 倍——扣分是纠偏不是惩罚，扣太狠学生算完账会直接放弃。

#### 预设只是初始数据，不是"内置功能"

这条要写死，因为它决定老师会不会改：

| 操作 | 预设项 | 自建项 |
|---|---|---|
| 改名、改分值、改图标 | ✅ | ✅ |
| 拖拽排序 | ✅ | ✅ |
| 删除 / 归档 | ✅ | ✅ |

界面上**不要**给预设项打"系统内置"标签，也不要加锁图标。一旦有锁，老师就会认定"这东西改不了"，然后绕开它另建一个同名的，最后榜单里两个「课堂发言」并存。

实现上只需要一列 `preset_key` 记录"它最初来自预设"，且这一列只被一个功能读：**恢复默认预设**（见 9.8）。全部删光、自己重建一套，也是完全合法的用法——预设只是省事，不是约束。

### 9.2 信息架构：两端不是同一套页面

**大屏端是操作面，电脑端是管理面，另有只读端给查询。** 同一个 exe，三种形态由**首次启动向导**选定（不再走启动参数），
页面集合不同——不是同一套界面缩放成两倍。

> v1.1 改动：形态从命令行参数收进向导管，并加了第三种形态「只读查询」。
> 参数一旦写死在快捷方式里，换台机器就会静默进错形态（大屏端没有导入入口，电脑端没有记分台），
> 而老师不会去改 `.cmd`。只读端则是需求本身：走廊那台机器只需要能查。

```
大屏端（教室一体机，触屏）              电脑端（办公室，键鼠）
┌────┬──────────────────┐          ┌──────┬──────────────────┐
│ 记 │  记分台            │          │ 总览 │  今日/本周概况     │
│ 分 │  ← 默认页          │          │ 名单 │  学生、座位、导入  │
│    │                   │          │ 成绩 │  导入、权重、排名  │
│ 看 │                   │          │ 打印 │  排名表、个人单页  │
│ 查 │                   │          │ 周期 │  重置、历史        │
│ 明 │                   │          │ 设置 │                   │
│ 设 │                   │          │      │                   │
│ 48 │                   │          │ 230  │                   │
└────┴──────────────────┘          └──────┴──────────────────┘
```

| 页面 | 大屏端 | 电脑端 | 为什么 |
|---|---|---|---|
| 记分台 | ✅ 核心 | ❌ | 记分必须站在教室里，对着一屏学生 |
| 看板 | ✅ | ❌ | 是给教室投影/屏保用的 |
| 查分 | ✅ | ❌ | 学生在教室里查，不在办公室查 |
| 明细 | ✅ 只看当天；**未认人时隐藏操作人列** | ✅ 全部 + 筛选 | 大屏上翻历史流水没人用；教室里公开屏幕，谁扣的分不能随便露 |
| 成绩/权重 | ❌ | ✅ | 见下 |
| 打印 | ❌ | ✅ | 打印机在办公室 |
| 名单 | 只读；仅向导里可**粘贴一列姓名** | ✅ 完整（Excel、学号、座位、分组） | 改名单是坐下来的活，不是站着做的 |
| 设置 | 仅本机项 | 全部 | 空闲时长归大屏，备份目录归电脑 |
| 事件计数 | ✅ 触屏加减 | ✅ 矩阵 + 改准确值 | 记事件和记分一样是站着做的，两处都要有 |
| 只读查询端 | — | — | 只有查分 / 排名 / 事件三页，**没有任何写入口**：不建会话、不启读卡器、同步只拉不推。放在走廊或办公机器上给学生自己查 |

页面之间的流转、状态与超时，见 9.9——**那才是这套界面真正的骨架**，各页面只是它的节点。

**成绩页为什么只放电脑端**：加权排名要调滑块、要比对、要反复预览前 20 名怎么变，这是"坐下来算账"的动作。放在教室那台 4K 触屏上，班主任得站着拖滑块，旁边的学生还在看。而且**大屏不该显示加权总评**——那是期末给家长的东西，不是日常给学生看的。大屏只显示积分，够用了。

### 9.3 记分台

见 4.2。三个细节：

- 卡片上分数是最大元素（36–44 px 半粗），姓名次之（20–22 px），今日变化最小（14 px，带 ↑↓）。
- 加分色用青绿 `#34D399`，扣分用砖红 `#F87171`，不用纯红纯绿——教室里"红绿"有指示灯语义，会干扰判断。完整色板见 9.10。
- 被扣分的学生卡片短暂显示红边 2 秒，不弹窗、不发问，避免公开羞辱。
- 分值只有类型默认分这一个来源；长按类型按钮可输入自定义值（见 4.8）。

### 9.4 看板（无人操作时的停留页）

- 深色底（`#12161C`），避免投影反光；文字高对比。
- 前 15 名 + 右侧最近 8 条动态。
- 每 **20 秒**在个人榜/小组榜间切换（设置页可调，默认 20），400 ms 淡入淡出。太快学生看不清名次变化，太慢一节课看不到几次切换。
- **常驻界面不显示任何按钮**，只在底部一行小字：「轻触屏幕 · 或直接刷卡」。按钮只在轻触后出现，避免学生围观时手贱乱点。
- 轻触任意位置 → 浮出两个按钮：**查分**（直接进）与**开始记录**（刷卡或密码）。不是直接进记分台，也不是直接进认人——学生查分不该被要求刷卡。
- **刷卡不用点任何东西**：NFC 监听在看板态常驻，班委碰一下卡就直接进记分台。这是最常用的一条路径，比"轻触 → 点开始记录 → 刷卡"少两步。

### 9.5 查分（学生自助）

看板是"全班看"，查分是"一个人看"。缺了后者，积分就只是老师的记账本——学生不知道自己的分怎么来的，激励就断了。

**入口**：看板态轻触屏幕，出两个按钮——

```
        ┌──────────────┐  ┌──────────────┐
        │   查 分       │  │  开始记录     │
        │  （直接进）    │  │（刷卡或密码）  │
        └──────────────┘  └──────────────┘
```

**学生网格不显示分数。** 这一条是刻意的：如果网格上就有分数，它就成了第二块公开榜单，那"点进去看自己"这个动作就毫无意义，而且会让排名靠后的学生站在屏幕前当众被围观。网格只显示**姓名 + 座位号**，按座位排（和学生记分台一致），学生一眼找到自己。

```
│  回答问题   ████████████  12 次   +120      │
│  早读背课文 ██████         6 次   +300      │
│  黑板演题   ██             2 次   +200      │
├────────────────────────────────────────────┤
│  最近记录                                  │
│  今天 10:24   回答问题       +10            │
│  昨天 15:02   早读背课文     +50            │
│  昨天 09:41   回答问题       +10            │
└────────────────────────────────────────────┘
```

**查分页只显示当前周期，不显示学期累计。** 大屏上出现两个"积分"（本月 1240、学期 3680），学生一定会问"我到底多少分"，而且两个数字都对，解释起来比不显示更糟。学期累计只在电脑端的总评里出现（8.2）。标题跟着周期名走——"11 月积分"，不是写死"本月"，因为有的班主任按学期重置。

**条形长度按"次数"画，不按分值。** 分值尺度拉开到 10–100 之后，按分值画会让一次黑板演题把其余七八项压成一条看不见的线，那张图就没法读了。次数是学生真正能对照自己的东西（"我发言 12 次"），分值放在右边做补充。

四个设计决定，每个都有代价，说清楚：

1. **不建学生账号，查分不需要任何认证。** 学生没有卡、没有 PIN、没有密码。代价是技术上防不住"点开别人的看"，但收益是零成本、零管理（48 个学生账号是一笔没人愿意维护的账）。
2. **用社交约束代替技术约束。** 个人页顶部用最大字号写"王小明 · 3 排 2 座"——旁边同学一眼就看到你在看谁。这比任何登录框都有效，而且不花一行代码。
3. **不显示操作人和备注。** 明细只给"时间 + 类型 + 分值"。谁扣的、备注写了什么，只有班主任在电脑端能看到。教室里是公开屏幕，这两个字段一旦露出，课间就会变成对质现场。
4. **高中生措辞避免名次羞辱。** 不写"第 38 名 / 共 48 人"，不写"倒数第 11"，写"第 38 名"+"距前一名 4 分"。**给的是追赶目标，不是位置判决**。这条看着虚，但对十五六岁的学生，措辞就是产品。

**两个必须做的细节**：

- **30 秒无操作自动退回看板，且退出时清屏。** 否则上一个人的分数会留在屏幕上，下一个人凑过来就看到了。
- **查分不写任何数据。** 纯只读路径，连访问日志都不记——记了就等于在库里留一份"谁什么时候查了分"，没必要。

**性能**：48 人网格 + 一次 `SUM` 聚合，本地库毫秒级。个人页的类型分布也是一次 `GROUP BY`，50 人的数据量下不必做缓存。

### 9.6 成绩页（仅电脑端）

四段，从上到下：考试列表 → 两层权重 → 排名预览 → 导出。

- **考试列表**：每场显示日期、满分（默认 750）、参考人数、缺考人数、导入时间；点进去能改满分或重导。**没有科目列**——一场考试就是一个总分，这是刻意的简化。
- **两层权重**：考试/平时两个联动滑块；下面是各场考试的权重表（每行一个滑块 + 一个数字框），底部实时显示合计。合计不等于 100% 时数字标红、导出变灰，旁边给「自动配平」。
- **滑块下面那行实时换算**：`名义 70 : 30 → 实际影响 37 : 63（考试均分 600、积分均 2400）`。这是 7.2 里最重要的一句，没有它老师不知道自己在调什么。
- **口径开关**：「总评折算成百分制」默认关闭，旁边写明"打开会改变部分学生名次"。改了立刻重排预览，让人当场看到后果。
- **排名预览**：默认前 20 名，拖滑块时 300 ms 内重排，并给一句"前 10 名中 2 人位次变化"。
- **导出**：按钮旁有个「导出前检查」，列出缺考未处理、权重不足 100%、有学生零积分三类问题。允许强制导出，但会把问题写进「参数说明」页。

50 行的表在触屏上滑动很累，默认收起，只展开前 20 名。

### 9.7 打印

期末有四样东西要落到纸上，而且**都不能靠"导出 Excel 再排版"**——班主任不会调列宽和页边距：

**排名表和总评表是两张，不是一张。** 贴在后墙的那张只印积分——总评是给家长的，贴出来等于把"谁考试差"公开到全班，而积分本来就公开。这两张分开，是一个不该省的区别。

| 版式 | 用途 | 规格 |
|---|---|---|
| **班级排名表** | 贴教室后墙 | A4 横向，50 人一页，名次/姓名/座位/积分。**默认不含总评**（勾选才加） |
| **期末总评表** | 评优、上报、存档 | A4 横向，名次/姓名/考试总分/考试百分制/平时分/总评，附权重与归一基准 |
| **个人成绩单** | 家长会一人一张 | A4 纵向，一人一页：各场考试总分与百分制、平时分（积分）、总评、班级排名、积分明细摘要 |
| **恢复卡** | 向导第 4 步生成 | 名片大小，印恢复码与配对说明，让老师塞进钱包 |
| **周期归档封面** | 装订存档 | A4 纵向，周期名、起止日期、记录条数、生成时间、校验码 |

**打印预览必须先有。** 直接弹系统打印对话框是不负责任的——第一次打出来歪了、少了半列，老师就不会再试第二次。预览页要能翻页、能缩放，且**所见即所印**（同一份 HTML，不是两套渲染）。

**分页必须在学生之间断开**，不能把一个学生的成绩单劈成两页。这条在 HTML 打印里靠 `page-break-inside: avoid`，在长表格里靠按行数切页，不要指望浏览器自动分页的品味。

技术上怎么做，见 10.6——结论是**不引入任何 PDF 库**。

### 9.8 设置页（两端）

**大屏端只放本机相关的项**，管理类的全在电脑端——否则老师在教室站着改备份路径，是很容易出事的那种"顺手操作"。

| 设置项 | 大屏端 | 电脑端 |
|---|---|---|
| 空闲回看板时长、音效开关、看板轮播 | ✅ | — |
| 管理模式密码、恢复码重生成 | ✅ | 只读查看 |
| 班委管理（发卡、注销、最近使用） | ✅ | ✅ |
| 学生名单、座位布局 | 只读 | ✅ |
| 加分项管理 | ✅ | ✅ |
| 权重方案 | — | ✅ |
| 备份目录与恢复 | — | ✅ |
| 历史周期 | 只读 | ✅ |
| 回收站（已删学生、已归档加分项，30 天内恢复） | — | ✅ |
| **设备配对 / 退出登录** | — | ✅ |
| 重新运行欢迎页 | 本机项 | 本机项 |

#### 加分项管理

列表一屏放完，每行就是 `拖拽手柄 │ 图标 │ 名称 │ − 分值 + │ 归档`，点行即编辑，不需要"编辑"按钮进二级页。**触屏拖拽必须有明显的插入指示线**：一条 4 px 强调色横线跟着手指走，行间距在拖拽时拉开 8 px，否则手指挡住的那一行根本看不出要插在哪。

点行展开的编辑区只有五项，多了就没人改：

| 项 | 控件 | 默认 |
|---|---|---|
| 名称 | 文本框 | — |
| 默认分 | 数字 + `±` | 按预设 |
| 封顶 | 下拉：不封顶 / 单次最多 ___ / 每周期最多 ___ | 早读背课文 = 单次 50 |
| 入账确认 | **固定开，不提供关闭** | 全部类型 |
| 图标 | 一排 12 个预设图标 | 按名称猜 |

**"封顶"是行内直接显示的**，不是藏在展开区里：每行右侧用小字标 `≤50`。老师扫一眼列表就知道哪几项有约束——藏起来的话，他会在课堂上被上限压回，然后回来到处找原因。

**"入账确认"不给开关，这是有意的。** 一旦可关，就会出现"我记得关过""到底关没关"的争论，而这个功能存在的意义就是每次都发生。省一步操作的价值，低于"分账永远对得上"的价值。

预设项和自建项在这张列表里长得一模一样，没有任何标记——原因见 9.1 最后一节。

**恢复默认预设**要写死三条行为，否则第一次误点就会出事：

1. **只追加缺失的 `preset_key`**。已存在的一律跳过，哪怕名字和分值都被改过，也绝不覆盖。
2. **不复活主动删除的项。** 想找回某个删掉的预设，单独走「查看已删除预设」的清单勾选恢复，不要塞进"恢复默认"里——那会让"删过的又回来了"变成一个灵异事件。
3. **执行前先给预览**：「将新增 3 项，跳过 5 项已存在」，确认才写。一句话的成本，换掉一整类投诉。

反向操作也要允许：清空全部预设、自己新建一套，是合法用法。预设只是省事，不是约束。

### 9.9 整屏会话：状态机、覆盖层、超时

前面八节是"每个页面长什么样"，这一节是"页面之间怎么走"。触屏应用最容易做坏的地方不是单个页面，而是**状态没人管**：班委走了屏幕还亮着记分台、框选了 12 人结果超时清空、管理模式开了半小时没人关。

#### 三个正交的状态位

不要用一个 `currentUser` 变量扛所有事。大屏端同时有三个互不干扰的状态：

| 状态位 | 取值 | 谁改它 | 影响什么 |
|---|---|---|---|
| **身份态** | `anonymous` / `identified` / `admin` | 刷卡、密码、超时 | 按钮可见性、能否写入 |
| **会话态** | `idle` / `scoring`（有选中）/ `composing`（键盘开着） | 触摸 | 返回键行为、超时是否生效 |
| **同步态** | `synced` / `pending(n)` / `offline` / `conflict` | 网络 | **只影响状态条，不阻塞任何操作** |

关键在于第三行那句话。同步态一旦允许阻塞 UI，就会退化成"网络一抖，老师点不动"——而这正是当初坚持"界面只读本地库"要避免的。

三个状态位组合出的"能不能写入"只有一张小表：

| 身份态 | 会话态 | 能否入账 |
|---|---|---|
| anonymous | 任意 | ❌（点卡片只弹"请先刷卡"） |
| identified | idle / scoring | ✅ |
| identified | composing | ✅（确认后回到 scoring） |
| admin | 任意 | ✅（admin 隐含 identified） |

#### 覆盖层，不是新页面

触屏上跳页会丢掉上下文——老师选了 12 个人，点"更多"跳出去，回来发现选择没了。所以**记分台之上的所有东西都是覆盖层**，底下那屏卡片永远在：

| 层 | 触发 | 覆盖范围 | 怎么关 |
|---|---|---|---|
| 数字键盘 | 长按类型按钮 500 ms | 下半屏，卡片仍可见 | 点空白 / 确认 / 下滑收起 |
| 认人卡 | 看板「开始记录」、或在 anonymous 态点了卡片 | 整窗（含遮罩） | 刷卡成功 / 30 秒超时 |
| 管理密码 | 改名单、改分值、撤别人、重置、封顶强制超出 | 居中卡片，背景可交互但被拦截 | 取消 / 连错 5 次锁 1 分钟 |
| 入账确认条 | **任意分值**入账前 | 底部一条 88 高，不遮卡片 | 点确认 / 取消 / 8 秒自动取消 |
| 撤销条 | 入账成功 | 底部一条，不遮卡片 | 5 秒自动消失 / 点撤销 / 点备注 |
| 冲突提示 | 同步返回 409 | 居中卡片，模态 | 必须选一个，不能点外面关 |

只有最后一条是强制模态的：冲突没解决之前，任何写入都会把两份数据搞得更乱。其余五种都可以"点外面关掉"，因为它们的代价只是重来一次。

**大屏端的键盘预算是零。** 分数用自绘数字键盘，管理模式密码用**同一套**键盘（6 位 PIN，九宫格 + 退格），理由只选标签，名单在电脑端改，学生姓名不做重命名。所以这台机器上不需要任何实体键盘、也不会弹任何输入法——这是"一体机常常没配键盘"这个事实倒逼出来的设计，不是简化。唯一的例外是班委刷卡：PN532 走 USB 转串口，电脑上就是一个 COM 口，程序开个后台线程每 150 ms 寻一次卡，**既不占输入焦点，也不需要键盘**（见 2.4）。这比键盘模拟那条路更贴这台机器的形态——键盘模拟方案要求界面上始终有个隐藏输入框抢着焦点，老师一点别处就失效。

**入账确认条默认 8 秒后按"取消"处理**，不是按"确认"。超时取消失败的代价是再点一次（2 秒），超时确认的代价是给 12 个人各加了 100 分（老师要一条条撤）。**所有"超时就默认执行"的设计，最后一定会执行错的那一次。**

8 秒这个值比撤销条的 5 秒长，因为确认条要留出"看一眼合计"的时间；但又不能太长，否则它会一直压在底部，挡住下一次操作。**新的一次点选会直接顶掉旧的确认条**（旧的按取消处理），不做队列——老师连点两个类型时，想的是"第二个"，不是"两个都要"。

#### 一次会话的完整流转

```
              ┌──────────────────────────────────────────┐
              │            board（看板 · 停留态）          │
              │  轮播个人榜/小组榜 · 20 秒切换 · 无按钮     │
              └───────┬──────────────────────┬───────────┘
       轻触屏幕        │                      │ 刷卡（NFC 常驻监听）
                      ▼                      ▼
              ┌───────────────┐      ┌──────────────────┐
              │ 选择：查分/记录 │      │ identified（班委）│
              └───┬───────┬───┘      │ 顶部显示姓名条    │
         查分     │       │ 记录      └────────┬─────────┘
                  ▼       ▼                    │
          ┌──────────┐  刷卡            ┌──────▼───────┐
          │  查分页   │                  │   记分台      │
          │ 30s 清屏  │                  │  idle/scoring │
          └──────────┘                  └──┬────┬───────┘
                                           │    │ 点管理入口
                              30s 无操作 ◄──┘    ▼
                                 回 board    ┌──────────────┐
                                             │ 密码 → admin  │
                                             │ 5 分钟无操作退出│
                                             └──────────────┘
```

四条规则值得单独记：

1. **刷卡监听在 `board` 和 `identified` 两态都常驻**。所以在看板前刷一下卡就能直接进记分台，不用先点"开始记录"。这是班委最常用的路径——站到机器前碰一下，两秒后就在记分了。
2. **`identified` 态再刷一张卡 = 换人**，不是叠加。换人前提示「当前是李思远，要换成张雨桐吗？」，确认才换。不提示的话，两个人先后刷卡，后一个会以为前一个没记完的分是自己的。
3. **管理模式的超时只退管理模式，不退身份**。班主任改完名单被叫走，5 分钟后回来，还是"已认人"的班主任（能记分），但改名单要重新输密码。退到看板就太重了——他还站在那儿。
4. **查分页超时直接回看板并清屏**，不回到"选择"那一屏。因为下一个人可能是班委要记分，让他多点一次没意义；而留在选择屏上，上一个人的分数还隐隐约约在那儿。

#### 三个超时，必须互不打架

| 超时 | 时长 | 触发条件 | 注意 |
|---|---|---|---|
| 看板轮播 | 20 秒（可调） | 始终 | 个人榜 ↔ 小组榜，切换时 400 ms 淡入淡出 |
| 班委会话 | 30 秒无操作 | 仅 `idle` 态 | **`scoring` 态不触发** |
| 管理模式 | 5 分钟无操作 | 仅 `admin` 态 | 退到 `identified`，不是 `anonymous` |
| 查分页 | 30 秒无操作 | 查分页内 | 回看板 + 清屏 |

第二条那个"仅 idle 态"是踩过才知道的细节：老师框选 12 个人之后，低头看一眼名单、或者转身喊一句"第三组站起来"，中间静默 30 秒很正常。这时候清空选择，他会当场骂人。**有选中项就不计时**，或者至少延长到 90 秒。

第四条反过来：查分页必须严格计时，而且退出时清屏。教室是公共空间，上一个人的分数留在屏幕上，下一个凑过来就看到了。

#### 中断与恢复

| 中断 | 行为 |
|---|---|
| 记分中途有人刷卡 | 提示换人确认；取消则保持当前会话，卡片选择**保留** |
| 记分中途断网 | 什么也不弹，状态条变「待同步 3 条」，其他一切照旧 |
| 窗口失焦（切到浏览器查名单） | 状态全保留，回来继续；不自动锁屏 |
| 一体机休眠 / 断电 | 本地库已提交，重开直接进记分台，outbox 继续推 |
| 数字键盘开着时超时到点 | **先关键盘，再重新开始计时**，不要在一次操作中间把人踢回看板 |
| 点卡片但还没刷卡 | 不弹密码框，弹一句「请先刷卡」+ 一个刷卡示意动画，3 秒后自动消失 |

最后一条容易做错：anonymous 态点卡片，最自然的实现是弹"请先认人"的模态框，但那会让第一次用的人以为要先登录。**点卡片仍然给视觉反馈（卡片浮起），只是分数不变**，配一句轻提示。让人知道"我点到了，只是没权限"，比弹窗友好得多。

#### 电脑端没有会话，但有长任务

电脑端免密，所以没有身份态流转。它的问题在另一个方向——**长任务**：

| 任务 | 典型耗时 | 必须有的东西 |
|---|---|---|
| 导入 50 人 Excel | 1–3 秒 | 进度条 + 可取消 + 预览确认（见 7.1） |
| 算 50 人加权排名 | < 300 ms | 直接算，不需要进度 |
| 导出四表 xlsx | 2–5 秒 | 进度条 + 完成后"打开文件 / 打开所在文件夹" |
| 打印 50 页个人成绩单 | 10–30 秒 | 逐页进度 + 可中途取消（已打的页不回收） |
| 整包导出 / 导入 | 1–10 秒 | 校验四件事（见 10.7），失败必须说清是哪一条不过 |

`async void` 事件处理器里做这些事，一旦抛异常就是静默崩溃——这是 WinUI 里最常见的"点了没反应"。所有长任务走 `IAsyncRelayCommand`，异常统一进一个 `TaskExtensions.FireAndForget` 包装，写日志 + 弹一句人话。

#### 空状态比正常状态更需要设计

五个页面在没有数据时分别长什么样，必须一次定完，否则开发时会各自"随便放一行灰字"：

| 页面 | 空状态文案 | 主按钮 |
|---|---|---|
| 记分台（无学生） | 「还没有学生。粘贴一列姓名就能开始，或者到电脑端导入 Excel。」 | 粘贴姓名 / 去电脑端 |
| 明细（本周期无记录） | 「这个周期还没有记录。课间加的第一条分会出现在这里。」 | 去记分台 |
| 成绩（未导入考试） | 「还没有导入成绩。支持 .xlsx 和 .xls，学号或姓名能自动匹配。」 | 导入成绩单 |
| 查分（无学生） | 「名单还没建好，找班主任。」 | — |
| 打印预览（无数据） | 「没有可打印的内容。」 | 返回 |

空状态的文案要**说下一步做什么**，不是陈述"暂无数据"。前者是引导，后者是死路。

### 9.10 UI 规划：按 WinUI 的真实尺度定，而不是凭感觉

我把 WinUI Gallery（微软官方的 WinUI 3 控件示例应用）在 1.0 缩放下量了一遍，得到这组基准值——**这些是 Fluent 给鼠标定的尺寸，触屏必须整体放大，但不能等比例放大**：

| 元素 | WinUI 默认（鼠标） | 实测来源 | 大屏端取值 | 倍数 |
|---|---|---|---|---|
| 左导航栏宽 | 230 DIP | Gallery 侧栏 | **48（收起）/ 230（展开悬浮）** | 0.21× / 1× |
| 导航项行高 | 32 DIP | Gallery 列表行 | 56 | 1.75× |
| 图标 | 16 / 32 | Gallery 卡片 | 24 / 40 | 1.5× |
| 卡片圆角 | 8 | Gallery 卡片 | 12 | 1.5× |
| 卡片描边 | 1 | Gallery 卡片 | 1.5 | 1.5× |
| 正文 | 14 | Segoe UI Variable Text | 20 | 1.43× |
| 页面标题 | 28–32 | Gallery 大标题 | 40 | 1.35× |
| 内容边距 | 24 | Gallery 内容区 | 12 | **0.5×** |
| 按钮高度 | 32 | Gallery 主按钮 | 72（类型按钮）/ 56（次要） | 2.25× |

两个反直觉的数字：

- **边距要缩小，不是放大。** 鼠标界面留白显精致，触屏 4K 上留白就是浪费——48 个学生要挤在一屏里，每 12 DIP 的边距都是从卡片宽度里扣的。
- **按钮放大的倍数比文字大。** 文字从 14 到 20（1.43×），按钮从 32 到 72（2.25×）。因为文字的可读距离决定字号，手指的落点精度决定按钮尺寸，两者不是一回事。等比放大会得到一个"字很大但按钮还是点不准"的界面。

#### 左侧导航：收起 48，展开 230，展开时不推挤

大屏端用 `NavigationView` 的 `PaneDisplayMode="LeftCompact"`：**平时只有一条 48 DIP 的图标条，点 ☰ 展开成 230 的悬浮面板。**

宽度账是这样：1920 DIP 减去收起态 48、再减去左右边距 24，剩 1848。8 列 × 222 + 7 × 10 = 1846——**刚好放下**。如果按标准 230 常驻，1896 − 230 = 1666，只能排 7 列，48 人从 6 行变 7 行，行高被压到 111，姓名和分数各降一档字号。**少一列 = 字号降一档 = 后排看不清**，这就是必须收起的唯一理由，不是审美。

展开时**压在内容上**（`IsPaneOpen` + 悬浮），不推挤网格。推挤会让 48 张卡片在展开瞬间重排一遍，视觉上像闪了一下，而且展开时你会看到列数变化——那正是最不该被打断的时刻。

```
大屏端（1920 × 1080，导航收起）              电脑端（键鼠，导航常驻）
┌────┬────────────────────────────────┐   ┌──────┬───────────────────┐
│ ▣  │ 高三(2)班·第12周   已选12人  ⟳ │   │ ☰ 班 │ 成绩 · 权重       │
│ ▤  ├────────────────────────────────┤   │      │                   │
│ ⊕  │ ┌──────┐┌──────┐┌──────┐  8 列  │   │ 总览 │ ┌───────────────┐ │
│ ☰  │ │王小明 ││李思远 ││张雨欣 │        │   │ 名单 │ │ 卡片 圆角 8   │ │
│ ⚙  │ │ 1240 ││  980 ││ 1510 │        │   │ 成绩 │ │ 1px 描边      │ │
│ 48 │ └──────┘└──────┘└──────┘        │   │ 打印 │ │ Mica 透出     │ │

```

**顶部那条 56 DIP 的状态条保留，但它只放状态，不放导航。** 班级名、已选人数、同步角标、刷新——这些东西在窗口化之后依然需要一条"标题带"，因为 Windows 的标题栏只有 32 DIP，放不下 20 号字。

**电脑端不收起。** 那里宽度不紧张，230 常驻，`NavigationView` 的折叠、键盘导航、无障碍全免费。两端用同一个控件、两种配置，不是两套代码。

**窗口化之后，导航的展开状态要跟着宽度走**：窗口宽度 < 1000 DIP 时强制收起且不给展开（展开会盖住半个网格），≥ 1000 时允许展开。这个判断放在 `SizeChanged` 里，和 4.1 的列数重算共用同一个防抖。

#### 大屏端要**反着** Fluent 官方建议走

微软文档推荐 Mica 背景、卡片投影、半透明材质。**这套在一体机上全要关掉**，理由在 4.9 已经算过（4 倍渲染缓冲区 + 核显 + 滑动框选要 55 fps）。这里补一条更硬的：Mica 会把桌面壁纸透上来，而教室一体机的壁纸大概率是学校统一推的蓝色风景图——**你的界面会变成蓝的**。固定纯色 `#12161C` 是唯一能保证对比度的做法。

代价是电脑端和大屏端看起来"不像同一个软件"。接受它：**它们本来就不是同一个使用场景**，一个是站着在 3 米外按，一个是坐着在 60 厘米外改。

#### 色板（只有 12 个值，多一个都不加）

| 用途 | 值 | 说明 |
|---|---|---|
| 大屏底色 | `#12161C` | 深蓝黑，投影下不刺眼 |
| 卡片底 | `#1C222B` | 与底色差 10 级亮度，够了 |
| 卡片描边 | `#2A3341` | 1.5 DIP，代替投影 |
| 选中描边 | `#4CC2FF` | 3 DIP，Windows 强调色，色盲友好 |
| 主文字 | `#F2F5F9` | |
| 次文字 | `#9AA7B8` | 今日变化、座位号 |
| 加分 | `#34D399` | 青绿，不用纯绿（避开"绿灯"语义） |
| 扣分 | `#F87171` | 砖红，不用纯红（避开"报错"语义） |
| 加分按钮底 | `#16352B` | 深底 + 亮字，比纯色块柔和 |
| 扣分按钮底 | `#3A1D14` | |
| 警告 | `#FBBF24` | 封顶、待同步 |
| 危险 | `#EF4444` | 只用于"重置"确认条 |

**不给主题切换。** 大屏固定深色，电脑端跟随系统。设置页里不出现"外观"这一项——多一个开关就多一倍截图和 bug，而这个软件没有人会为了好看去调它。

#### 分数用等宽数字

`FontFeatureCollection` 打开 `tnum`，或者直接用 `Cascadia Mono`。原因很实际：滑动框选时全班 48 个分数在变，比例数字会让整块网格左右抖，眼睛会晕。这一条在截图里看不出来，但一动就能感觉到。

#### 控件选型：哪些用现成的，哪些必须自绘

| 需求 | 用什么 | 自绘？ | 原因 |
|---|---|---|---|
| 电脑端导航 | `NavigationView` | 否 | 折叠、键盘、无障碍全免费 |
| 大屏端页签 | 自绘 `TabStrip`（56 高胶囊） | **是** | `NavigationView` 顶部模式太窄，`TabView` 带关闭按钮和拖拽，全是噪音 |
| 学生网格 | `ItemsRepeater` + `UniformGridLayout` | 是（模板） | 必须虚拟化；48 张含阴影的 `Border` 会掉帧 |
| 类型按钮 | `Button` + 自定义 `ControlTemplate` | 是 | 默认 `Button` 高 32、圆角 4，触屏不合格 |
| 数字键盘 | `Grid` + `Button` | 是 | 系统软键盘慢且遮屏（见 4.8） |
| 确认条 / 撤销条 | `InfoBar` 改造 | 是 | 标准 `InfoBar` 是"信息条"形态，我们需要两个按钮 + 合计数字 |
| 电脑端设置页 | `SettingsCard`（Community Toolkit） | 否 | 省 300 行样式，且和系统设置页一致 |
| 状态提示 | `InfoBar` | 否 | 同步失败、新版本、迁移提示都用它 |
| 空状态 | `StackPanel` + 图标 + 两个按钮 | 是 | 一次做成控件，五个页面复用（见 9.9 末） |

**"自绘"只针对大屏端。** 电脑端能用的标准控件一律不重写——那里是键鼠，Fluent 默认尺寸就是对的，重写只会引入无障碍问题。

#### 交付顺序上的一个建议

先做**电脑端的名单页和成绩页**，再做记分台。听起来反了（记分台才是核心），但理由成立：记分台的开发需要真实名单和真实分值在库里，否则每次调样式都要手填假数据；而电脑端两个页面恰好是产生这些数据的入口，且它们是标准控件，两天能出形。

真正的风险在记分台的手势和 4K 尺寸，那部分必须等真机到位再动（见文末附录的一天验证）。

## 十、工程与实现要点

### 10.1 环境、依赖与分发

**开发只需要一台机器**：Visual Studio 2026 + 「WinUI 应用开发」工作负载 + .NET 10 SDK。CI 那边不一样，见 10.8——WinUI 的打包必须跑在 Windows 上，这一点没有绕路。
- Windows 11（一体机通常预装），.NET 10 SDK
- Visual Studio 2026 + 「WinUI 应用开发」工作负载
- Windows App SDK **2.6.5**（2026-11-02 稳定版；修了多显示器渲染崩溃与窗口透明异常，触屏一体机常外接投影，务必用这个版本）
- **读取 Excel 用 NPOI，导出用 ClosedXML**：NPOI 同时支持 `.xls` 和 `.xlsx`（学校的教务系统十有八九导出旧格式），ClosedXML 生成带样式的新表更顺手。两套库各管一头，比硬拧一个省心
- WebView2 运行时（Win11 自带；打印与 PDF 全靠它，见 10.6）
- **串口读卡不需要任何第三方 NFC 库**：`System.IO.Ports`（读 COM 口）+ `System.Management`（按设备描述找端口）就够，帧解析自己写四十行，见 2.4。**不要引 libnfc**——它在 Windows 上要拿 Zadig 把 CH340 换成 WinUSB，换完串口就废了

#### 装到老师手上是什么样

"安装尽量简便"这句话，对教室场景有具体含义：**老师没有管理员权限，也不敢点"是"**。所以四种形态里只有一个合格：

| 形态 | 老师要做的 | 下载体积 | 问题 |
|---|---|---|---|
| MSIX | 先装根证书，再装包 | ~80 MB | **必须签名证书**。让一位班主任在"证书导入向导"里点六次"下一步"，这一步就会劝退九成人；学校组策略还常直接拦 MSIX |
| 单文件 exe（`PublishSingleFile`） | 双击 | ~180 MB | 首启要解压到 temp，3–5 秒白屏；WinUI 的 `resources.pri` 在单文件模式下有已知坑。看着最简，实际最脆 |
| **安装包（Inno Setup，per-user）** ← 主推 | 双击 → 下一步 → 完成 | 75 MB / 装后 230 MB | 无。装进 `%LOCALAPPDATA%`，**不弹 UAC**，不写注册表服务项，卸载走系统"应用和功能" |
| 免安装 zip ← 备选 | 解压 → 双击 exe | 75 MB | 要自己建快捷方式；适合 U 盘拷、机房无网、或装在 D 盘 |

安装包和 zip 是同一份 `dotnet publish` 产物，只是打包方式不同，所以两条路不会出现"zip 版有 bug、安装版没有"这种最恶心的情况。

```ini
; installer.iss 关键三行
PrivilegesRequired=lowest
DefaultDirName={localappdata}\ClassPoints
OutputBaseFilename=ClassPoints-Setup-{#AppVersion}
```

`PrivilegesRequired=lowest` 是重点：它让安装全程不弹 UAC，装到用户目录，卸载干净。代价是"所有用户"装不了——教室里只有一个人用这台机器，这个代价为零。

**自动更新不能静默。** unpackaged 应用没有 App Installer，所以自己做一个最小的：启动 3 秒后异步 `GET /latest.json`（放 R2 或 GitHub Release），版本更高就在顶部弹一条 `InfoBar`：「有新版本 v1.4（当前 v1.3）· 下载」。**不要自动下载安装**——教室一体机可能正在上课，静默重启是不可接受的行为。下载就是打开浏览器到 Release 页，让老师自己决定什么时候装。

#### 装完不改任何系统设置

上一版列了"开机自启、关睡眠、强制全屏"三件事，这一版全删。理由不是它们没用，是**这一版的使用方式和它们冲突**：

- **不自启。** 软件是窗口化的普通程序，谁用谁打开。开机就把记分台推到屏幕上，等于把"这个班正在记分"变成机器的默认状态——课间没人在的时候，屏幕上也停着一屏学生的分数。而且自启是最典型的"装完就忘、出问题最难查"的东西。
- **不动电源设置。** 那台一体机本来就没有睡眠设置。退一步说，就算它黑屏，`AppWindow` 的窗口状态和本地库都不受影响，唤醒后一秒内继续用。**绝不调 `powercfg`**——改了别人的电源计划，卸载还不还原，是最招人烦的一类软件行为。
- **不强制全屏。** 普通窗口，可拖、可缩放、可最小化。**首次启动给 1920 × 1048 居中**（这个尺寸刚好 8 列 × 6 行放下 48 人，见 4.1），工作区不够就退到 90%；用户调过之后就记住。

所以安装包真正要做的只有一件事：**记住窗口位置和尺寸**。

```csharp
// 退出时存，启动时还原；还原前夹回当前工作区，防止换小屏后窗口跑到屏幕外
var wa = DisplayArea.GetFromWindowId(AppWindow.Id, DisplayAreaFallback.Nearest).WorkArea;
var want = settings.WindowRect ?? new Size(1920, 1048);   // 首次：8 列 6 行刚好，见 4.1
var r = new Rect(
    wa.X + Math.Max(0, (wa.Width  - Math.Min(want.Width,  wa.Width )) / 2),
    wa.Y + Math.Max(0, (wa.Height - Math.Min(want.Height, wa.Height)) / 2),
    Math.Min(want.Width,  wa.Width),
    Math.Min(want.Height, wa.Height));
AppWindow.MoveAndResize(r);
```

**卸载时唯一要清的**是 `%LOCALAPPDATA%\ClassPoints` 里的数据库和设置——但**默认不删**，只在卸载向导里勾选「同时删除本机数据」时才删，并且默认不勾。一学期的流水，卸载时顺手清掉是最不可原谅的失误。

顺带一条不做的：**不要注册为 Windows 服务，也不要装计划任务。** 教室里那台机器是给人用的，一个后台常驻服务只会在出问题时让你多一个要排查的东西。

### 10.2 云端：Worker 与 D1

**这一层要薄。** 它不做业务计算（不排名、不折算），只做四件事：鉴权、校验、幂等写入、增量查询。把所有计算留在客户端，是为了让"换云端只改 Repository"这件事真的成立。

```
worker/
├─ wrangler.toml
├─ migrations/
│  └─ 0001_init.sql          # 就是第六章的 DDL，去掉本地专属表
└─ src/
   ├─ index.ts
   ├─ auth.ts                # 配对、刷新 token、设备 SID 绑定
   ├─ sync.ts                # GET /sync?since=
   └─ routes/{entries,students,rules,periods,exams}.ts
```

```toml
name = "classpoints-api"
main = "src/index.ts"
compatibility_date = "2026-11-01"

[[d1_databases]]
binding = "DB"
database_name = "classpoints"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

[vars]
TOKEN_TTL_HOURS = "12"
REFRESH_TTL_DAYS = "90"
```

**接口只有十个**，多一个都不要加：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/classes` | **创建班级**（仅大屏端向导第 1 步），返回班级码 + owner 凭据 |
| POST | `/api/v1/pair` | 班级码 + 密码（或恢复码）→ access + refresh token |
| POST | `/api/v1/refresh` | 静默续期 |
| GET | `/api/v1/sync?since=&limit=` | 增量拉取（学生/规则/流水/周期/考试与成绩，含墓碑） |
| POST | `/api/v1/entries` | 批量提交 1–50 条，整批一个事务 |
| POST | `/api/v1/entries/batch/:id/reverse` | 按批次撤销（见 6.5） |
| POST | `/api/v1/exams` | **一场考试 + 全部成绩**，整批一个事务，按 `(exam_id, student_id)` UPSERT |
| POST | `/api/v1/:entity` | 新增（`students` / `rules` / `members` / `note_templates`），带客户端 UUID |
| PATCH | `/api/v1/:entity/:id` | 修改，带 `If-Match: rev`；不匹配返回 409 |
| POST | `/api/v1/periods/reset` | 两阶段：申请令牌 → 提交 |

十行、八个端点族——`POST` 与 `PATCH` 共用 `:entity` 算一族，`/entries/batch/:id/reverse` 归 entries 族。`/classes` 是最容易漏的一个：向导第 1 步要建班，而它只调用一次，写接口表时很容易想不起来。

`/exams` 单开一个端点，理由和 `/entries` 一样：**它是成批的事实数据，不是单条实体。** 一场考试 1 条 exam + 48 条 score，用 `:entity` 逐个 POST 就是 49 次往返，跨境到 Cloudflare 每次 100–300 ms，导一次成绩要等 15 秒。整批一个事务，一次往返，失败就整场回滚——成绩导入要的就是这个原子性。

`note_templates` 走 `:entity` 是刻意的：它没有特殊逻辑，就是一张会被两端改的小表，硬给它单开一个端点只会多一套校验。**但它必须进同步**——老师在教室点选过的标签，晚上在办公室也要能用；不然这个功能就只在半台设备上成立。

**幂等靠两条约束，不靠代码判断**：

```sql
CREATE UNIQUE INDEX uq_entries_id ON entries(id);              -- 客户端 UUIDv7
CREATE UNIQUE INDEX uq_entries_reversal ON entries(reverses_entry_id)
  WHERE reverses_entry_id IS NOT NULL;                          -- 同一批次只能撤销一次
```

配合 `INSERT OR IGNORE`，重传自然幂等，不需要"先查再插"。

**`db.batch()` 在 D1 里是一个事务，且只算一次查询配额**——50 条记录走 batch 消耗 1 次而不是 50 次，这个差别在免费额度下很关键。

**成本**（免费额度够不够）：

| 项目 | 免费额度 | 50 人一个班/天 | 20 个班 |
|---|---|---|---|
| Worker 请求 | 10 万/天 | 约 600 | 约 1.2 万 |
| D1 读行 | 500 万/天 | 约 3,000 | 约 6 万 |
| D1 写行 | 10 万/天 | 约 300 | 约 6,000 |
| D1 存储 | 500 MB | 约 12 MB/学期 | 约 240 MB |

单班远远用不完。真要超，只可能是存储，升 Workers Paid（$5/月）即可。

### 10.3 批量入账（一次事务、一个批次）

```csharp
public sealed record AwardItem(string StudentId, string RuleId, string RuleLabel,
                               int Delta, string? Note);

public async Task<string> ApplyBatchAsync(
    IReadOnlyList<AwardItem> items, Member op, string method, DateTime? occurredAt = null)
{
    var batchId = Guid.NewGuid().ToString("N");
    var now = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();

    await using var conn = await _db.OpenAsync();
    await using var tx = await conn.BeginTransactionAsync();

    foreach (var it in items)
    {
        var cmd = conn.CreateCommand();
        cmd.Transaction = tx;
        cmd.CommandText = """
            INSERT INTO entries
              (batch_id, period_id, student_id, rule_id, rule_label, delta, note,
               operator_id, operator_name, identify_method, occurred_at, created_at)
            VALUES ($b, $p, $s, $r, $l, $d, $n, $o, $on, $m, $oa, $ca)
            """;
        cmd.Parameters.AddWithValue("$b", batchId);
        cmd.Parameters.AddWithValue("$p", _currentPeriodId);
        cmd.Parameters.AddWithValue("$s", it.StudentId);
        cmd.Parameters.AddWithValue("$r", it.RuleId);
        cmd.Parameters.AddWithValue("$l", it.RuleLabel);
        cmd.Parameters.AddWithValue("$d", it.Delta);
        cmd.Parameters.AddWithValue("$n", (object?)it.Note ?? DBNull.Value);
        cmd.Parameters.AddWithValue("$o", op.Id);
        cmd.Parameters.AddWithValue("$on", op.DisplayName);
        cmd.Parameters.AddWithValue("$m", method);
        cmd.Parameters.AddWithValue("$oa", occurredAt?.ToUnixTimeMilliseconds() ?? now);
        cmd.Parameters.AddWithValue("$ca", now);
        await cmd.ExecuteNonQueryAsync();
    }

    await tx.CommitAsync();
    return batchId;      // 撤销条用这个 id
}
```

本地 SQLite 写入，50 条插入在一个事务里约 1–2 ms，完全不需要异步队列或批量合并——**这是本地镜像白送的性能**，也是「界面只读本地库」这条设计的直接回报。

### 10.4 本地库初始化

```csharp
var csb = new SqliteConnectionStringBuilder
{
    DataSource = Path.Combine(AppDir, "classpoints.db"),
    Pooling = true,
    DefaultTimeout = 5
};
var conn = new SqliteConnection(csb.ToString());
conn.Open();
using (var cmd = conn.CreateCommand())
{
    cmd.CommandText = """
        PRAGMA journal_mode = WAL;       -- 读写不互锁，断电可恢复
        PRAGMA synchronous = NORMAL;     -- WAL 下足够安全，比 FULL 快一个量级
        PRAGMA foreign_keys = ON;
        PRAGMA busy_timeout = 5000;
        """;
    cmd.ExecuteNonQuery();
}
```

`AppDir`：未打包应用放 `%LOCALAPPDATA%\ClassPoints\`。**不要放程序目录**——一体机上程序可能装在 `Program Files`，普通用户没有写权限。

**建表与写种子分两步，别混在一起。** 建表看版本号（`PRAGMA user_version`），种子看 `settings.onboarding_done`。混在一起会出事：向导第 3 步允许用户改分值甚至全删，如果启动时"发现 rules 为空就补种子"，用户删光预设重启一次，它们会全部复活。

**只有一套预设，三行，没有学段分支。** 上一版的三套模板和"换学段"逻辑一并删掉——你们就是高中一个班，多一套模板只是多一个选错的入口。

```sql
-- 只在 onboarding_done 为空时执行一次；INSERT OR IGNORE 保证重复执行无害
INSERT OR IGNORE INTO rules
  (id, label, delta, icon, sort, preset_key, cap_value, cap_scope) VALUES
  ('r_speak',  '回答问题',       10, '💬', 10, 'std.speak',  NULL, NULL),
  ('r_recite', '早读检查背课文',  50, '📖', 20, 'std.recite',   50, 'single'),
  ('r_board',  '课上黑板演题',  100, '🖊️', 30, 'std.board',   NULL, NULL);
```

**`delta` 和 `cap_value` 都是 50 的那一行，不是笔误。** 早读这一项默认分就是上限，含义是"背完给满，背得差往下调"（见 4.8）。

`preset_key` 前缀统一用 `std.*`，只被「恢复默认预设」读。三个 id 用固定字符串而不是随机 UUID，是为了让这个按钮幂等：补几次都只有三行。

**以后加项走两条路，都不改这份种子。** 一是老师在设置页点「＋ 新建」；二是你把班规发我，我加进种子并升一次 `user_version`——后者只影响全新安装，老库不会被自动塞新行（那会让"我没建过这项"变成说不清的事）。

### 10.5 备份（这一节别跳过）

```csharp
// 每天首次启动 + 每 50 次入账，各触发一次
public async Task BackupAsync()
{
    var stamp = DateTime.Now.ToString("yyyyMMdd-HHmm");
    var dir = Path.Combine(BackupRoot, stamp);

    // 1) 数据库一致性副本（不要直接复制文件，用 VACUUM INTO）
    await ExecAsync($"VACUUM INTO '{Path.Combine(dir, "classpoints.db")}'");

    // 2) 人可读的 xlsx 快照
    var xlsx = BuildWorkbook(await BuildRankingAsync(), _currentScheme);
    await File.WriteAllBytesAsync(Path.Combine(dir, "积分快照.xlsx"), xlsx);

    // 3) 清理：保留最近 30 天 + 每月 1 号的那份
}
```

`VACUUM INTO` 会生成一个干净的一致性副本，比 `File.Copy` 安全（后者可能拷到写了一半的 WAL）。备份目录默认在本地，设置页允许改到 U 盘或 OneDrive 同步目录。有了云端，本地备份不再是唯一防线，但它仍然必要：**断网、Cloudflare 抽风、或者哪天真要换国内云的时候，手边得有一份能立刻打开的数据**。恢复速度也是本地快一个数量级。

界面上要显示：「上次备份：今天 14:03」，超过 3 天变橙色，超过 7 天变红色并弹一次提示。给非技术用户做软件，这类提醒比功能重要。

### 10.6 打印：一份 HTML，预览和打印是同一份

**不引入任何 PDF 库。** 这看起来反直觉，但理由很硬：

| 方案 | 问题 |
|---|---|
| QuestPDF | 功能最好，但 Community License 明确排除 **public-sector bodies**。公立学校算不算，边界模糊；要给年级推广，就得买 Enterprise（$4,999/年）。为了打四张表付这个代价不值 |
| iText / Syncfusion | AGPL 或商业授权，同样的问题 |
| XAML `PrintDocument` | 免费，但分页、缩放、页眉页脚全要手写，一套代码要处理五种版式，很容易做出"打出来少半列"的效果 |
| **HTML + WebView2** | WinUI 3 自带 WebView2，Win11 预装运行时。**预览和打印用的是同一份 HTML**，所见即所印 |

做法就三步：

```csharp
// 1) 把数据套进 HTML 模板（字符串拼接或 Razor，不需要模板引擎）
var html = PrintTemplates.RankingTable(students, period, scheme);

// 2) 预览：直接把这段 HTML 灌进预览窗口里的 WebView2
await previewWebView.EnsureCoreWebView2Async();
previewWebView.NavigateToString(html);

// 3) 打印：同一份 HTML，两种出口
var core = printWebView.CoreWebView2;
await core.PrintToPdfAsync(pdfPath, new CoreWebView2PrintSettings {
    Orientation = CoreWebView2PrintOrientation.Portrait,
    ShouldPrintBackgrounds = true,
    ShouldPrintHeaderAndFooter = false   // 否则会印出 file:/// 的 URL
});
// 或直接弹系统打印对话框：
// await core.ShowPrintUIAsync();
```

**六个坑，按踩到的概率排序**：

1. **`ShouldPrintHeaderAndFooter = false`**。默认是 true，打出来页脚会印着 `about:blank` 或者一长串本地路径。第一次打印必然踩。
2. **等渲染完成再打**。`NavigateToString` 是异步的，紧接着调 `PrintToPdfAsync` 会打出空白页。等 `NavigationCompleted` 再等 100 ms（字体加载）。
3. **分页要在学生之间断开**：`table tr { page-break-inside: avoid; }`，配合 `@page { size: A4 landscape; margin: 12mm; }`。不要指望浏览器自动分页的品味。
4. **字体只用系统自带的**（`Microsoft YaHei`、`SimSun`）。Web 字体在教室断网时加载不出来，打出来是方块。
5. **`PrintToPdfAsync` 的目标文件被占用会抛异常**——预览窗口如果正开着同一个 PDF，第二次导出就失败。导出前先检查并换个文件名。
6. **打印机可能是 A4 也可能是 A3**。版式按 A4 设计，A3 会自动缩放，别为两种纸各做一套。

**五种版式的模板放在一个 `PrintTemplates` 静态类里**，共用一段 CSS（页边距、表头、斑马纹、页脚"导出时间 + 校验码"）。页脚那行很重要：纸上也要能自证是哪一版数据。

### 10.7 整包迁移：换机、重装、交接

一体机会坏，系统会重装，班主任会换人。**一学期的数据不能只活在一块硬盘上**，这是 10.5 备份要解决的；但备份解决的是"数据还在"，不解决"新机器能直接用"。所以需要整包迁移：

```
classpoints-20261108-1430.zip
├─ manifest.json          # app_version / schema_version / exported_at /
│                         # entry_count / student_count / sha256(db)
├─ classpoints.db         # VACUUM INTO 出来的一致性副本
├─ settings.json          # 座位布局、空闲回看板时长等本机配置
└─ README.txt             # 一段人话：怎么导入、找谁
```

**导入时校验四件事，任何一条不过就拒绝**：

1. `sha256(db)` 与 manifest 一致 —— 排除拷贝损坏；
2. `schema_version` **不大于**当前程序版本 —— 来自更新版本的库，直接提示"请先升级程序"，不要尝试读；
3. `entry_count` 与库里的实际行数一致 —— 排除半截包；
4. 导入前把现有库改名为 `classpoints.db.bak-<时间戳>` —— **不覆盖，只并排**。用户装错了包还能退回去。

**升级走 `PRAGMA user_version` 阶梯**，每个版本一个函数，顺序执行，全部在一个事务里：

```csharp
var migrations = new (int From, string Sql)[] {
    (1, "ALTER TABLE students ADD COLUMN rev INTEGER NOT NULL DEFAULT 1;"),
    (2, "ALTER TABLE rules ADD COLUMN preset_key TEXT;"),
    // …
};
```

两条规则：**升级前强制自动备份**（升级失败还能回滚），**不允许降级**（旧程序打开新库会静默丢字段，比报错危险得多）。

**云端也在升级**：Worker 先部署（向后兼容），客户端后发。顺序反了，旧 Worker 遇到新字段会 400，全班当场不能用。这条在多端场景下是常识，在"两台设备"里同样成立。

### 10.8 开源、仓库与云编译

#### 先纠正一个前提

"上传 cnb 开源并云编译"这条路，我查了平台文档，结论和预期不同，直接说：

- **CNB 的托管构建节点没有 Windows。** 只有 `cnb:arch:amd64`、`arm64`、GPU 三种 Linux 节点。Windows/macOS 构建机属于**自托管 Runner**，要你在「组织设置 → 构建节点」里自助接入，且社区版这个入口默认不开放，得联系平台管理员开通。
- **WinUI 3 也没法在 Linux 上交叉编。** 不是 .NET 的问题，是 WindowsAppSDK 的 MSBuild target 要调 Windows SDK 里的 `makepri.exe`（生成 PRI 资源）和 `mt.exe`（清单嵌入），这两个是 PE 可执行文件。用 wine 跑有人试过，在 CI 里不稳定，不值得赌。
- 所以「push 一下，CNB 直接吐出 Setup.exe」目前**做不到**。任何说能做到的方案，都是没真跑过。

#### 能做的：拆成两段

| 在哪跑 | 跑什么 | 触发 | 产出 |
|---|---|---|---|
| **CNB**（托管 Linux 节点，免费 160 核时/月） | Worker 类型检查 + 单测 + 部署；**Core 库单测**；文档 | 每次 push | 红叉/绿勾，D1 迁移 |
| **GitHub Actions**（`windows-latest`，免费） | `dotnet publish`、Inno 打包、出 Release | 打 tag | `ClassPoints-Setup-1.4.0.exe` + zip |
| CNB 自托管 Windows Runner（可选） | 同上，全在 CNB 内 | 打 tag | 同上；需要一台常开的 Windows 机器 |

前提是**代码分层要撑得住**：业务逻辑必须待在一个不引 Windows 的库里。

```
classpoints/
├─ .cnb.yml
├─ .github/workflows/build-winui.yml
├─ src/
│  ├─ ClassPoints.Core/      # net10.0。折算、封顶、排名、积分规则、导入解析
│  ├─ ClassPoints.Data/      # net10.0。SQLite、outbox、同步协议
│  ├─ ClassPoints.App/       # net10.0-windows。只有 XAML 和平台胶水
│  └─ ClassPoints.Tests/     # xUnit，Linux 上能跑
├─ worker/
├─ installer/installer.iss
└─ docs/
```

`Core` 和 `Data` 一行 Windows API 都不能有。这不只是为了 CI —— 折算公式、封顶扣减、排名并列处理这些最该有单测的东西，如果在 `App` 里，就只能靠人肉点界面验。**把"能在 Linux 上跑测试"当成架构约束，代码质量会跟着变好。**

#### `.cnb.yml`

```yaml
main:
  push:
    - stages:
        - name: worker 类型检查与单测
          image: node:22
          script: |
            cd worker
            npm ci
            npm run typecheck
            npm test
        - name: Core 单测（折算 / 封顶 / 排名）
          image: mcr.microsoft.com/dotnet/sdk:10.0
          script: |
            dotnet test src/ClassPoints.Tests -c Release --logger "console;verbosity=normal"

# tag 不属于任何分支，所以 tag_push 是顶层键，不要缩进到 main 里
tag_push:
  - stages:
      - name: 部署 Worker 与 D1 迁移
        image: node:22
        script: |
          cd worker
          npm ci
          npx wrangler d1 migrations apply classpoints --remote
          npx wrangler deploy
```

`CLOUDFLARE_API_TOKEN` 放 CNB 的密钥仓库，不要写进 yml。迁移和部署挂在 `tag_push` 而不是 `push`：**每次提交都自动改线上库，迟早会出事。** 顺带一提，`tag_push` 缩进到 `main:` 下面是最常见的写法错误——yml 不报错，但打 tag 时流水线永远不触发，你会以为是平台没收到事件。

#### `.github/workflows/build-winui.yml`

```yaml
name: build-winui
on:
  push:
    tags: ['v*']
  workflow_dispatch:

jobs:
  windows:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '10.0.x'

      - name: Publish (self-contained, unpackaged)
        run: >
          dotnet publish src/ClassPoints.App/ClassPoints.App.csproj
          -c Release -r win-x64 -p:Platform=x64 --self-contained true
          -p:PublishReadyToRun=true -o out/app

      - name: Zip (免安装版)
        run: Compress-Archive -Path out/app/* -DestinationPath out/ClassPoints-${{ github.ref_name }}-win-x64.zip

      - name: Setup 安装包
        run: |
          choco install innosetup --no-progress -y
          & "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" /DAppVersion=${{ github.ref_name }} installer\installer.iss

      - uses: actions/upload-artifact@v4
        with:
          name: win-x64
          path: |
            out/*.zip
            out/*.exe
```

`windows-latest` 自带 VS2022 和 Windows SDK，WindowsAppSDK 走 NuGet 还原，不需要额外装什么。整个 job 大约 6–9 分钟，在免费额度内。

如果你确实想把编译也收到 CNB：在组织设置里接入一台 Windows 机器当 Runner（家里那台常开的台式机就行），`.cnb.yml` 里加

```yaml
tag_push:                                   # 顶层键，与 main 平级
  - runner:
      namespace: group
      tags: [windows]
    stages:
      - name: publish
        script: |
          dotnet publish src/ClassPoints.App -c Release -r win-x64 --self-contained true -o out
```

两个坑：自托管 Runner 上 `stage script` 默认走 **PowerShell** 不是 bash（`&&` 能用，`export` 不能）；它也不开 Docker，所以 `runner.cpus` 和 `docker.image` 都无效，机器上装了什么就用什么。

#### 产物能不能推到 CNB 的 Release？能，但不直传

能。CNB 有一套 OpenAPI（`https://api.cnb.cool`），Release 附件走的是**两段式上传**：先向 CNB 申请一个 COS 直传凭证，再 `POST` 到对象存储。不是"一次 PUT 上去"，这是第一个坑。

三个前提，缺一不可：

1. **CNB 上要已经存在这个 tag 和对应的 Release。** 附件挂在 Release 上，Release 不存在就没地方挂。`GET /{repo}/-/releases/tags/{tag}` 能查到 id 才行，所以 GitHub 打 tag 之后要先让 CNB 收到同一个 tag（同一个仓库镜像，或手动建），或者在 job 里调一次创建接口。
2. **一个 CNB 访问令牌**，存在 GitHub 仓库的 `secrets.CNB_TOKEN`。权限选"仓库读写"，别用个人全权限令牌。
3. **`jq`**，`windows-latest` 自带。

```yaml
      # 接在 upload-artifact 之后；只在打 tag 时跑
      - name: 镜像到 CNB Release
        if: startsWith(github.ref, 'refs/tags/')
        shell: bash
        env:
          CNB_TOKEN: ${{ secrets.CNB_TOKEN }}
          CNB_REPO:  your-group/classpoints      # 改成你的 CNB 仓库路径
          TAG:       ${{ github.ref_name }}
        run: |
          API=https://api.cnb.cool
          H=(-H "Authorization: Bearer $CNB_TOKEN" -H "Accept: application/vnd.cnb.api+json")

          # 1) 取 Release；不存在就建一个空壳（先有 Release，才能挂附件）
          if ! curl -fsS "${H[@]}" "$API/$CNB_REPO/-/releases/tags/$TAG" -o rel.json; then
            curl -fsS "${H[@]}" -X POST "$API/$CNB_REPO/-/releases" \
                 -H "Content-Type: application/json" \
                 -d "{\"tag_name\":\"$TAG\",\"name\":\"ClassPoints $TAG\"}" -o rel.json
          fi
          echo "release id: $(jq -r .id rel.json)"

          # 2) 逐个文件：申请凭证 → 表单直传 COS → 附件即挂上
          for f in out/*.zip out/*.exe; do
            name=$(basename "$f")
            curl -fsS "${H[@]}" -X POST \
                 "$API/$CNB_REPO/-/upload/releases/$TAG?asset_name=$name" -o up.json

            url=$(jq -r '.url' up.json)
            # form 是一个对象，逐字段拼成 -F
            args=(); while IFS=$'\t' read -r k v; do args+=(-F "$k=$v"); done \
              < <(jq -r '.form | to_entries[] | "\(.key)\t\(.value)"' up.json)

            curl -fsS "${args[@]}" -F "file=@$f" "$url" -o /dev/null
            echo "uploaded $name"
          done
```

**第一次跑一定要把 `up.json` 打出来看一眼**（`cat up.json`）。不同版本的 OpenAPI 在返回字段上有细微差别（`form` 是对象还是字符串、字段叫 `url` 还是 `upload_url`），照抄别人的脚本大概率在第三行就挂。这一步不值得赌，值得花五分钟对一次。

**更省事的替代方案：走 git，不走 API。** 构建完把 `out/*.zip`、`out/*.exe` 提交到一个 orphan 分支 `dist`，push 到 CNB；CNB 侧在 `dist` 分支的 push 流水线里用官方插件 `cnbcool/attachments` 挂附件：

```yaml
main:
  push:
    branches: [dist]
    - stages:
        - name: 挂到 Release
          image: cnbcool/attachments:latest
          settings:
            type: UPLOAD
            tag: $TAG_FROM_COMMIT_MESSAGE     # attachments 需要一个 tag
            attachments: "*.zip,*.exe"
```

代价是要把二进制塞进 git 历史（一个 75 MB 的安装包，几十个版本就把仓库撑到几 GB）。**所以推荐前者**：产物只活在 Release 里，仓库只存源码。

**但要想清楚为什么镜像。** 唯一站得住的理由是**下载速度**——GitHub Release 在国内经常几十 KB/s，75 MB 的包要下十分钟，老师会以为卡死。CNB 在国内有 CDN，这一点确实值。如果只是"想两边都有"，那是负担：两套发布点、两份要维护的链接、两个可能不同步的版本号。**建议：GitHub 是唯一发布点，CNB 只做镜像，README 里两个链接都写，注明"国内优先用 CNB"。**

另一个更彻底的选择是先别做这件事。第一次发布就一个老师下载，GitHub 慢一点也能忍；等你把安装包发到第三个同事手上、他抱怨下不动，再加这 30 行 yml，一点都不晚。

#### 开源协议和一件必须写进 README 的事

**协议用 MIT。** 不是因为它最好，是因为它最不吓人：一位老师想把界面改成自己学校的名字、加一个"周考核"字段，看到 AGPL 会直接关掉页面。

**仓库里绝不能有真实学生数据。** 这是这类项目最容易犯、后果最重的错：一次 `git add .` 把 `students.xlsx` 推上去，48 个未成年人的姓名和成绩就永久留在公开历史里了（git 历史删不干净，fork 和缓存都有一份）。

```gitignore
*.db
*.sqlite
*.sqlite3
*.xlsx
*.xls
*.csv
data/
backups/
*.bin          # 导出的整包
```

提交前跑一次，输出必须为空：

```bash
git ls-files | grep -Ei '\.(db|sqlite3?|xlsx?|csv)$'
```

`samples/` 里的示例名单全部虚构（张三、李四、王五…），README 第一行写明"示例数据均为虚构，与任何真实班级无关"。演示截图里的姓名也要换成虚构的——**打码不够，码下面的原名可能还在图层里**。

#### 三条工程约定

1. **`main` 永远可发布。** 功能在 `dev` 上做，合并前 CI 必须绿。一个人维护的项目，最怕的是"主分支跑不起来，只有我本地能跑"。
2. **数据版本单调递增，不允许降级。** 库里的 `user_version` 只增不减，旧程序打开新库要明确拒绝（见 10.7）。云端 D1 迁移先跑，客户端后发。
3. **README 写死"一个部署 = 一个班级"。** 开源后一定有人问"能不能一个学校装一套"，答案是不能：当前模型没有 `class_id`，多班要重做数据模型。写清楚比事后解释便宜。

## 十二、风险与取舍

下面是这套设计里刻意接受的风险与各自的对策。看懂这几条，就知道哪些地方**不该**再改。


| 风险 | 后果 | 对策 |
|---|---|---|
| **硬盘损坏 / 电脑丢失** | 一学期的记录全丢 | 云端已有全量数据，重装后配对即恢复；本地备份只是加速，不再是唯一防线 |
| **每次入账多一步确认** | 高频场景下老师嫌慢，转身用纸记 | 确认条不遮卡片、按钮位置固定，两周内形成肌肉记忆；上线后实测"10 人批量加分"耗时，若明显超过 15 秒再回来商量（但默认不给关闭开关） |
| **卡可克隆**（CUID 卡 UID 可写） | 学生用手机 + MCT 复制班委卡，冒名加分 | 接受这个事实，把卡定位成「认人」不是「授权」：管理操作全要 PIN，刷卡只切记分身份，每条记录带 `identity_id` 可追溯；卡丢了 `revoked_at` 立即吊销。详见 2.4 末节 |
| **人脸合规** | 未成年人敏感信息，家长质疑 | 首版不做，接口预留；若要做，必须家长书面同意 + 特征只存本地不上传 |
| **班主任一个人维护系统** | 嫌麻烦，用两周放弃 | 班委必须有独立记账权限；导入导出必须一键完成；所有配置有默认值 |
| **数据落在境外** | 学校或家长追问时说不清 | 见 5.7：以 D1 为主，国内云留门。真被追问时能给出一句准确回答——数据在香港/新加坡，本班 48 人的名单与积分，可随时导出并切到国内服务器 |
| **成绩单比预想的更乱** | 导入出来缺人、错行，老师当场不信这个功能 | 预览页逐行标状态、汇总行明说"忽略 N 行"、同名与人名校验都不自动决定；**用三份真实成绩单先做回归**，别只试自己班那份 |
